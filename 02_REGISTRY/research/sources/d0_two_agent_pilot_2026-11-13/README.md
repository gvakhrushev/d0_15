Перед новым раундом получите актуальный снимок из Git.

```sh
git fetch origin
git rev-parse origin/codex/d0-pilot-shared-20261118
```

Для чтения используйте отдельное чистое рабочее дерево. Укажите этот SHA при передаче следующего результата. Добавляйте результат в свою папку `direct/roundN` или `open/roundN`, ссылайтесь на уже опубликованную работу по относительному пути и передавайте SHA координатору. Координатор обновляет общую ветку и этот индекс. [Критерии приёмки](../../A4D_SCOPED_NATIVE_KAPPA_CONTRACT_2026_11_03.md).

Перед началом новой задачи внесите в таблицу ниже вопрос, владельца, участок записи и базовый SHA. Сначала опубликуйте эту запись и проверьте её в удалённой ветке. Если вопрос уже занят, используйте его результат по ссылке или согласуйте отдельную проверку. Общая ветка принимает проверенные положительные результаты, контрпримеры и частичные выводы с указанной границей применимости.

Публикуйте каждое законченное доказательство вместе с исходными данными или ссылкой на их закреплённую версию, командой проверки и областью применимости. Обновите ссылку в индексе и передайте агентам путь и SHA. После одновременных публикаций получите свежую версию, объедините чужие изменения и повторите обычную отправку. Для проверки доступности результата всем агентам задайте переменной `result_sha` SHA опубликованного коммита.

```sh
git fetch origin
git merge-base --is-ancestor "$result_sha" origin/codex/d0-pilot-shared-20261118
```

Код завершения 0 подтверждает, что коммит входит в общую удалённую историю.

## Как вести четыре направления

У каждого исследователя свой участок записи и свой способ приблизиться к общему утверждению. В начале раунда зафиксируйте исходную версию, конкретную историю и какой неизвестный член можно вычислить или исключить. Подзадачи и выбор доказательства определяет сам исследователь. Новые результаты дают три вида свидетельств: выведенный отклик, проверяемое достаточное условие или точный пример, который опровергает предложенную склейку. Указывается область каждого утверждения.

| Направление | Какой результат передаёт соседям |
|---|---|
| Полная запись и часы | Операторный отклик или оценку относительно действительного усиления поля, до и после переноса вариаций |
| Исходные веса сцены | Формулу отображения её упорядоченных весов в исполнение либо наблюдаемое расхождение на той же истории |
| Приготовление и команды | Короткую оплачиваемую программу с предсказуемыми выходами, различающую допустимые способы нормировки |
| Совпадение уравнений | Условие на полный источник на известном решении и компоненты, которые не удаётся устранить сменой масштаба |

Сигналом к обмену служит новый вывод, подходящий как вход встречной проверки. Дожидаться завершения остальных направлений для этого не требуется. Координатор проверяет совпадение носителя, смысла цены и допустимых вариаций. Если две группы использовали разные часы или разные задачи, в отчёте фиксируется требующий доказательства переход. Глобальный статус ОТО меняется только после научной проверки исходного контракта.

Каждый раунд может иметь свой индекс `portfolio.json`. В нём для каждого направления записаны результат, граница применимости, следующий различающий опыт и путь к самостоятельной проверке. Общий запуск воспроизводит проверки параллельно, проверяет SHA-256 указанных материалов и выводит результат каждого направления. В текущем раунде используются Python, SymPy, NumPy и SciPy.

Из этой папки выполните `python3 -B verify_portfolio.py direct/round73/portfolio.json`. Для сквозной проверки раундов 62–73 в zsh или bash выполните `python3 -B verify_portfolio.py direct/round{62,63,64,65,66,67,68,69,70,71,72,73}/portfolio.json`. По умолчанию одновременно идут четыре проверки; каждая выдаёт результат сразу по завершении. Число одновременных проверок задаётся параметром `--jobs N`.
