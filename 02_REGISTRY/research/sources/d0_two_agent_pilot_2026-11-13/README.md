# Параллельный пилот D0 → ОТО

Единый источник текущих результатов — ветка [`codex/d0-pilot-shared-20261118`](https://github.com/gvakhrushev/d0_15/tree/codex/d0-pilot-shared-20261118/02_REGISTRY/research/sources/d0_two_agent_pilot_2026-11-13). Ветка собрана поверх исследовательской базы [#334](https://github.com/gvakhrushev/d0_15/pull/334). Текущая научная граница `GR_closed=false` проверяется по исходному контракту A–D.

| Раздел | Кто ведёт | Откуда начинать |
|---|---|---|
| [Directed](direct/) | Directed исследует исходное исполнение, условия допуска и перенос в полевые уравнения | [Задачи и опубликованные отчёты A](#текущие-задачи). Команда ниже даёт последний отчёт по SHA. |
| [Open](open/) | Open независимо проверяет реализации и остаток полной цены | [Задачи и опубликованные отчёты B](#текущие-задачи). Команда ниже учитывает также новые публикации между обновлениями таблицы. |

Перед выбором задачи сверяйте также [сводный реестр основного исследования ОТО](https://github.com/gvakhrushev/d0_15/blob/exp/a4d-joint-response-continuation-2026-10-16/02_REGISTRY/research/sources/d0_gr_2026-11-18/README.md) в PR #334. В нём собраны исходные пакеты, тесты работы, циклов и полного источника.

Для нового чата используйте [инструкцию исследователю D0](AGENT_START_RU.md). Из каталога пилота одна команда получает из Git свежую таблицу, показывает владельцев открытых задач и даёт постоянные ссылки на последние отчёты обоих режимов. Она обнаруживает повтор номера раунда и битые ссылки в таблице. Смысловое совпадение вопросов проверяют участники по формулировке и владельцу.

```sh
python3 -B pilot_status.py
```

Для воспроизведения статуса на конкретном SHA добавьте `--revision SHA`. Для чтения используйте отдельное чистое рабочее дерево. Укажите этот SHA при передаче следующего результата. Добавляйте результат в свою папку `direct/roundN` или `open/roundN`, ссылайтесь на уже опубликованную работу по относительному пути и передавайте SHA координатору. Координатор обновляет общую ветку и этот индекс. [Критерии приёмки](../../A4D_SCOPED_NATIVE_KAPPA_CONTRACT_2026_11_03.md).

Перед началом новой задачи внесите в таблицу ниже вопрос, владельца, участок записи и базовый SHA. Сначала опубликуйте эту запись и проверьте её в удалённой ветке. Если вопрос уже занят, используйте его результат по ссылке или согласуйте отдельную проверку. Если два чата одновременно подали заявки на один вопрос, его ведёт владелец первой заявки в удалённой истории. После отклонённой отправки перечитайте таблицу до повторной публикации и освободите дублирующую заявку. Для независимого воспроизведения запишите отдельно, какое допущение или результат проверяется. Общая ветка принимает проверенные положительные результаты, контрпримеры и частичные выводы с указанной границей применимости.

Публикуйте каждое законченное доказательство вместе с исходными данными или ссылкой на их закреплённую версию, командой проверки и областью применимости. Обновите ссылку в индексе и передайте агентам путь и SHA. После одновременных публикаций получите свежую версию, объедините чужие изменения и повторите обычную отправку. Для проверки доступности результата всем агентам задайте переменной `result_sha` SHA опубликованного коммита.

```sh
git fetch origin
git merge-base --is-ancestor "$result_sha" origin/codex/d0-pilot-shared-20261118
```

Код завершения 0 подтверждает, что коммит входит в общую удалённую историю. Открывайте итоговый отчёт по его SHA, а актуальные назначения — в таблице текущей ветки. Для нового чата передайте ссылку на эту таблицу, закреплённый отчёт и один ещё не занятый вопрос. Результат считается доступным другим агентам после публикации в удалённой ветке.

Из каталога пилота можно воспроизвести семь расчётов A84 по закреплённому снимку из 28 файлов. Семь первичных проверок #334 исполняются из двух собственных коммитов и побайтово сверяются с их результатами.

```sh
git fetch origin exp/a4d-joint-response-continuation-2026-10-16
OPENBLAS_NUM_THREADS=1 python3 -B verify_portfolio.py --git-snapshot bf6fac1a3a700967bafba2b88704ae0720818316 direct/round84/portfolio.json
```

## Как вести четыре направления

У каждого исследователя свой участок записи и свой способ приблизиться к общему утверждению. В начале раунда зафиксируйте исходную версию, конкретную историю и какой неизвестный член можно вычислить или исключить. Подзадачи и выбор доказательства определяет сам исследователь. Новые результаты дают три вида свидетельств: выведенный отклик, проверяемое достаточное условие или точный пример, который опровергает предложенную склейку. Указывается область каждого утверждения.

| Направление | Какой результат передаёт соседям |
|---|---|
| Полная запись и часы | Операторный отклик или оценку относительно действительного усиления поля, до и после переноса вариаций |
| Исходные веса сцены | Формулу отображения её упорядоченных весов в исполнение либо наблюдаемое расхождение на той же истории |
| Приготовление и команды | Короткую оплачиваемую программу с предсказуемыми выходами, различающую допустимые способы нормировки |
| Совпадение уравнений | Условие на полный источник на известном решении и компоненты, которые не удаётся устранить сменой масштаба |

Сигналом к обмену служит новый вывод, подходящий как вход встречной проверки. Дожидаться завершения остальных направлений для этого не требуется. Координатор проверяет совпадение носителя, смысла цены и допустимых вариаций. Если две группы использовали разные часы или разные задачи, в отчёте фиксируется требующий доказательства переход. Глобальный статус ОТО меняется только после научной проверки исходного контракта.

Каждый раунд может иметь свой индекс `portfolio.json`. В нём для каждого направления записаны результат, граница применимости, следующий различающий опыт и путь к самостоятельной проверке. Общий запуск воспроизводит проверки параллельно, проверяет SHA-256 указанных материалов и выводит результат каждого направления. В текущем раунде используются Python, SymPy, NumPy и SciPy.

Из этой папки выполните `python3 -B verify_portfolio.py direct/round79/portfolio.json`. Для сквозной проверки раундов 62–79 в zsh или bash выполните `python3 -B verify_portfolio.py direct/round{62,63,64,65,66,67,68,69,70,71,72,73,74,75,76,77,78,79}/portfolio.json`. По умолчанию одновременно идут четыре проверки; каждая выдаёт результат сразу по завершении. При наличии в индексе ссылок на первичные Git-объекты запуск сверяет и их содержимое с закреплёнными версиями. Число одновременных проверок задаётся параметром `--jobs N`.
