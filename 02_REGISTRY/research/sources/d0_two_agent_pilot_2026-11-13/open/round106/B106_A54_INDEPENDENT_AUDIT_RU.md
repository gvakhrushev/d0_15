# B106. Независимая проверка интеграции A54

**Результат: условный PASS для зафиксированной конструкции A54.** Независимо пересчитаны связывание SOURCE, все 1 048 576 пар group/CODE нового link, девятиуровневая рекурсия с буквальными inverse, полная верхняя стоимость SOURCE и global replacement, а также рациональные ошибки. Заключение использует проверенные ранее контракты A53/B103/B104 и исходные A48/A23/B25; оно относится к выбранному canonical fibre, а не доказывает тождество произвольному исходному маркированному descriptor. `physical_C_closed=false`, `GR_closed=false`.

[Проверяющий код](audit_a54_independent.py) и [receipt с SHA](B106_A54_AUDIT_CHECK.json). Зафиксированы SHA всех шести научных файлов A54, проверены зависимости двух его receipts. Полное гигантское слово и полный production path sum не запускались.

## Маршрутизация и SELECT

Расписание содержит каждую из 1568 SOURCE-копий ровно один раз: 1440 Choi и 128 CAR. Для каждой копии и depths 0, 1, 2 через настоящий `stage_blocks` с заменёнными на записывающие providers сверены kind, bank, depth и все 5376 CODE wires: 4704 вызова. Отдельно проверены непересечение фактических DATA/private targets между копиями и со всеми CODE wires, старый compiler helper и общий birth count `11893774624`. Экземпляр и обе вложенные части используют **один и тот же** immutable FieldCentre.

Для каждого bank fixed и variable link addresses различны, variable имеется только в f. Coframe и link занимают разные адреса; адрес 0 отсутствует во всех этих списках. Для всех 256 f-link groups перебраны 4096 слов digits: карта шести собственных координат, двенадцати low/high CODE wires и patterns совпадает с определением двухбитного поля. Поэтому variable provider читает собственное поле каждой группы; фиктивная общая xy-cache не проверяла бы это условие. Порядок fixed→variable и обратный порядок variable→fixed, с количеством буквальных обращений 0–3, отдельно испытан на независимом символическом splice. Исходный B93 variable-word в этом splice не вызывается.

На каждом из 496 различных `(i,j)` Julia32 planes в обоих направлениях вызван настоящий геометрический sector emitter с инструментированным SELECT. Проверены все target/control disjointness, допустимый размер до 29 и отсутствие записи в CODE как у SELECT, так и у CX-перестановок. Это проверка **геометрии**, а не повторная сертификация конкретных 496 углов: последняя наследуется из B103 и A54. Для coframe/CAR соответствующий all-width аргумент и выборочные полные операторы уже проверены B104; неизменённые SITE, prefix, vacuum, REPORT и A29 compiler сохраняют контракт A48. При этих контрактах нет G/CX target на CODE, хотя CODE может быть control. Утверждение не получено только из подготовленной нулевой колонки.

Для controlled Omega prefix фиксирован, а coframe/link SELECT тождественны при branch=0 и на адресе 0. На идеальном исходном prefix нормировка даёт `J_0=I32` и положительный anchor `1/sqrt(65568)` независимо от поля. Это основание прежней phase correction, при условии унаследованного A21 prefix contract; данная проверка не заявляет равенства произвольных intermediate marks.

## Буквальная обратимость и оплаченный inventory

Непосредственно вызван level-nine adapter с записывающими листьями. Для каждого начального depth 0, 1 и 2 наблюдается ровно `3^9=19683` вызова Omega; их depths имеют независимое распределение

    count(depth=d+j) = binom(9,j)·2^(9−j),   j=0,…,9.

Тем самым внутренние inverse-of-inverse реально остаются в дереве. Для стоимости независимо восстановлена линейная карта буквального обращения

    (Gport,Gother,CX,I) → (Gport+Gother,0,CX+6·Gother,3I+4(Gport+Gother)).

Отдельной формулой пересчитаны Walsh blocks для всех widths 1–29 и обоих видов patterns. Для link 496 planes имеют не более восьми дополнительных CX на plane. Без вызова A54 `native_budget` восстановлены fixed link upper, каждый bank Omega, все девять шагов адаптера, Choi RAW и reflections, CAR vacuum и оба frame preparations, затем сумма по **реальному** списку всех source slots. Полученные componentwise upper совпадают с A54. Это верхняя оценка; не объявляется точным числом операций без padding.

Независимо добавлены 8 REPORT, их RAW, обе resource-frame части, сохранённые port/SC6 расходы, буквально обращённый global A и центральный SourceI. Для компилятора использовано не более `8·W_SourceI` base-angle units; восстановленный `W_G_CX_upper` совпадает с A54. Замена удовлетворяет `<2^-15800`. Конкретные G/CX слова и angle values остаются ленивыми, а стоимость чисто классического выбора показателей не входит автоматически в физический clock.

## Ошибки, fibre и B105

В точных рациональных числах пересчитано `e_Omega=e_prefix+498·2^-3460`, `e_half` для `3^9` листьев, `1440 e_Choi+128 e_CAR+e_SITE`, восемь REPORT и compiler replacement. Получены A54 bounds SOURCE prefix `<2^-3423`, canonical compressed comparator `<2^-3421`. Максимум ошибок coframe/link SELECT допустим из-за проверенной непересекаемости address/CODE sectors; стоимость суммируется по всем sectors.

Область — все указанные SOURCE DATA/SITE columns с **canonical RAW Choi-private24 и CAR-predicate3**, допускается внешняя запутанность. При гибридном сравнении ещё не использованные private каждой следующей копии сохраняют canonical inputs. Это не норма на произвольных dirty private. Исходный A24 target использует полное конкретное A23 vacuum/Fourier продолжение, а полевой target — те же A23/B25 formulas, что и B91; B103 меняет представление Julia32, а не B25 target. Поэтому A54 error подходит для B105 positivity на **этой выбранной конструкции** вместе с B91 `||DB||≤1748` и A49 base `M_b(0)>67/100`. Вывод B105 `M_b(Y)>669/1000` остаётся условным на эти унаследованные результаты и CODE-support.

Отдельный незакрытый пункт: A23 явно выбирает полное унитарное продолжение vacuum подготовки. A23 и B91 не доказывают, что его действие на всех ортогональных входных columns, его marks и платная история совпадают с каким-либо ранее принятым другим исходным owner descriptor. Совпадение подготовленного vacuum state и малая ошибка A54 этого не устанавливают. Нужны допуск именно выбранного A23 descriptor либо доказанный marked-map transport к реальному descriptor, в том числе точное сопоставление `D_ν` и границ. Ни A54, ни B105 не закрывают это требование.

Также остаются физический carrier/action/gate и `V_h`, fine instrument/suffix, все независимые source rows, same-execution Cost−Info и GR refinement. Полевой `U_post(Y)` меняется с Y; не доказана нулевая source-stationarity при `Y≠0`.
