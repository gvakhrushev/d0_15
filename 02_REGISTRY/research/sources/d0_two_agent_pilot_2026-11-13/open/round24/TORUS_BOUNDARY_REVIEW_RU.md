# B24. Периодическая стыковка L=4: проверка зависимости и границ вывода

**Вывод:** при фиксированных PF-весах, collar и exterior-значениях предложенная замена открытого поперечного stencil на исходный периодический L=4 **не меняет ни одну source-производную по 2 688 свободным полям**. Это подтверждено полным структурным перебором всех 256 base sites, шести четырёхрёберных граней, четырёх материальных forward edges и всех `16+24+2` направлений в каждом из 64 свободных sites. Меняются ровно 112 source-строк; ни одна из них не зависит от свободного поля. Можно использовать исходный периодический CAR/Fourier carrier и конкретный периодический геометрический адресный контракт `A=2049` без добавления материального halo.

Это результат о **выходных скалярных функциях и их ограниченных source-производных**, при явно указанных ниже общих параметрах и moment-интерфейсе. Он не делает открытый polynomial halo частью фактического физического writer и не доказывает совпадение полных квантовых состояний, марок, сроков и историй. Если исходная задача требует независимых граничных направлений или полного поля за пределами выбранного chart, этот локальный результат не заменяет их проверку. `GR_closed=false`.

## 1. Полный stencil и центральный вывод

`X={0,1,2,3}^4`; свободны ровно `x2,x3∈{1,2}`, все 42 координаты в каждом таком site, `m=64·42=2688`: 16 additive raw inverse-coframe `u`, 24 proper-link Lie coordinates и две компоненты Psi. Для исходной coframe `e=nu eta u^(−T)` это локально обратимая замена всех 16 направлений. Верхний и нижний поперечный collar, включая все 16 coframe, 4·6 link и 2 matter directions, фиксирован. В open-сравнении также фиксированы реальные exterior operands на `x2=4` и `x3=4`; эта фиксация — условие математического сравнения, не предположение о готовом open writer. Продольные координаты `0,1` периодичны в обоих выражениях, PF `w_x=N_x/10946` и reference fields фиксированы.

Для каждой `r<s` оба выражения используют исходный порядок

```
U_r(x) U_s(x+e_r) U_r(x+e_s)^−1 U_s(x)^−1.
```

Только сдвиг по поперечному `r∈{2,3}` при `x_r=3` различается: open использует `4`, torus использует `0`. Если это происходит, сам base лежит на верхнем collar. Каждый другой фактор той же грани имеет тот же фиксированный `x_r=3`, а изменённый сдвинутый фактор имеет `x_r=0` либо `4`. Поэтому **каждый из четырёх link operands такой грани фиксирован**. Это включает пересечение `(r,s)=(2,3)` и угол `(x2,x3)=(3,3)`; свободный shifted link в такую изменённую грань не попадает. Локальный coframe этой строки также фиксирован.

Для материального `D_r^+Psi_A(x)`, `A=0,15`, единственное различие — target `4` против `0` при `x_r=3`; и base, и оба target фиксированы. Норма metric для `q_x` зависит от base coframe и тоже фиксирована. `R2` — поточечный полином каждого link operand; применение `R2`, exterior lift, истинного sharp inverse на правильной секции и CAR contraction не создаёт зависимости от других узлов. Для остальных строк **все локальные operand lists совпадают**; они могут зависеть от свободного поля, например при `x2=0` и forward target `x2=1`, и поэтому их нельзя просто объявлять постоянными.

[check_torus_binding.py](check_torus_binding.py) проверяет именно это по каждому присвоенному `sam_index`, а не на нескольких направлениях:

* 112 потенциально изменённых строк, PF-вес `4557/10946`; 144 строки с одинаковыми operands, вес `6389/10946`.
* 368 изменённых face instances: по 64 для `(0,2),(0,3),(1,2),(1,3)` и 112 для `(2,3)`. Двойной верхний угол учитывается один раз. Также 128 отдельных изменённых matter edges.
* Все зависимости `f` и `q` каждой изменённой строки от 2 688 chart coordinates пусты; остальные строки имеют одинаковые open/torus зависимости. Перебор видит все 2 688 имён и 128 source rows, потенциально достижимых от этих имён. Пустая зависимость — структурный результат для всех допустимых значений полей, не численная проверка в центре.

Полный [SITE_DEPENDENCIES.jsonl](SITE_DEPENDENCIES.jsonl) сохраняет для каждой строки face operands, torus programme addresses, материальные пары и реальные множества `sam_index`; [TORUS_CERTIFICATE.json](TORUS_CERTIFICATE.json) содержит сводку. Адресный анализ намеренно не определяет величины/нормировку произвольного вне-section quantum variation.

Контроль необходимости условий: если свободен завернутый collar-value `t`, то даже игрушечный forward square с base `0`, exterior `2`, torus target `t` даёт `q_torus−q_open=t²−4` и производную `2` при `t=1`. Если переменным сделать PF-вес, его произведение с постоянным boundary-сдвигом тоже даёт ненулевую производную. Эти контрпримеры иллюстрируют область теоремы и не являются дополнительной физической реализацией.

## 2. Семь исходных банков и среднее после компаратора

Используются одинаковые общие `Lambda_h`, comparator, полярность, физически совместимая нормировка входных moments, reference constants и одна и та же field-independent `alpha_h` там, где сравниваются scalar laws. Достаточно сравнения идеальных исходных функций: выполнение второго open native writer не предполагается. Для каждого `b` исходная семёрка — `y+,y−,f,0,x+,x−,q`:

* `f` содержит `Z_f=(e_b,U_b,0,rho)`, `q` — `Z_q=(e_b,I,Psi_b,rho)`; их локальные `H_f,x`/`H_q,x` читают настоящий source stencil. В пределах данного chart их open/torus разность зависит только от фиксированных строк.
* `0,x+,x−,y+,y−` используют фиксированные reference fields и исходную полную десятизначную report law. При соответствующем frame transport из §3 их ссылки дают одни и те же заданные `(0,0),(±k0 δ,0),(0,±δ)` на обеих геометрических конвенциях.
* В каждой из 7 report-программ исходные sign-moments получаются на независимо **регенерированных** полных Choi/CAR ресурсах. Изменение глобального размера Choi-программы меняет её state и оператор чтения, но у правильно перенормированного anchor соответствующие локальные моменты равны: `H_aij=(32A/2)(|r><s|+h.c.)` читает `Re J_a[j,i]` для каждого используемого адреса. Поэтому совпадение локальных operands переносится на указанные scalar moments; оно не является равенством полных Choi states при `A=2049` и `A=2433`.

При общем `SITE` выражение остаётся

```
Xi_x=(P_y+−P_y−)(P_f−P_0)+(P_x+−P_x−)(P_q−P_0),
Q=κ p^7 [4 + sum_x w_x Xi_x].
```

Если `x` не на верхнем collar, все действительные operands и `P_j` совпадают. Если `x` на верхнем collar, все потенциально изменённые `P_j` фиксированы относительно `b`, как и `w_x`; значит `sum_x w_x(Xi_torus−Xi_open)` есть одна константа на **всём** chart. Следовательно `D_b Q_torus=D_b Q_open`, и аналогично для целевого `c=1−2Q` и `I_tau` при одном и том же определении положительного `g`. Общий baseline `c`, полная условная вероятность и константа значения `I_tau` могут отличаться: их нельзя удалить или приравнять без отдельного вычисления. Криволинейные proper-link coordinates в chart этому не мешают: изменённые operands вне его, а все остальные полностью одинаковы до дифференцирования.

Это утверждение не автоматически распространяется на разные отдельно сконструированные native фабрики: совпадение их `alpha`, физической цены, marks или ошибок пока не показано. При finite native compilation потребуется собственный реальный error budget для каждого marked prefix. Совпадение физического memory-valued `C` и Book Cost−Info также не следует.

## 3. Конкретный torus programme и правильные reference frame / coframe

Периодический каталог [TORUS_CHOI_ADDRESSES.jsonl](TORUS_CHOI_ADDRESSES.jsonl) содержит один identity anchor, `256·4=1024` coframe и `256·4=1024` proper-link addresses, то есть `A=2049` **активных** адресов. У каждого site все 6 четырёхзвенных faces адресуются сдвигами modulo 4, все 5 material positions принадлежат исходному 256-site Fourier carrier. Реализация сохраняет раздельные внешний общий PF SITE, внутренний site/CAR/RIGHT каждой копии, отдельный неизвестный `D/oldRIGHT` и реальный RAW/factory work по B23.

Для одной полной Choi-копии:

```
b[a,i,j]=J_a[j,i]/sqrt(32·2049),   b_anchor²=1/65568,
active dimension=2049·32²=2 098 176, padded dimension=2^22,
O_b=I+K+K²/(1+<r,b>),  K=|b><r|−|r><b|.
```

Padding не входит в нормировку `A`; на его комплементарных колонках `O_b=I`. [check_torus_choi.py](check_torus_choi.py) выполнил эту низкоранговую карту на настоящих численных B21 centre targets `u_raw`, проверил anchor, обратную карту и padding без плотной матрицы `2^22 × 2^22`. Точность: ошибка ортогональности Julia `<2.3e−15`, обратного хода `<1.8e−14`. Это одна центральная numerical target-проверка, не sample-palette compilation.

**Поправка B23:** A11-интерфейс геометрического source использует `u_raw=nu eta e^(−T)` из §7eh.B(F1) и обратный PF-фактор ровно один раз. `sqrt(rho)`-dressed coframe из B21 является отдельной кандидатной конвенцией и не подставляется сюда без явного перерасчёта всей карты. Оценка B21 для добавки `4s` относится именно к additive `u`, а не к additive `e`. [TORUS_CHOI_TEST.json](TORUS_CHOI_TEST.json) использует именно raw array.

Согласование **текущего** null-frame также проверено: `R=diag(1,1,−1,−1)` есть собственное Lorentz-преобразование, для исходного `e0=I+H E_10/2` имеем `e=R e0`, `u=R(nu eta e0^(−T))=nu eta e^(−T)`, а для связей `U=R exp(Kx N2+Ky N3) R^−1=exp(−Kx N2−Ky N3)`. [check_current_frame.py](check_current_frame.py) точно проверяет эти тождества для символического H, полный 4-CAR creator covariance, exterior-метрику и обратимость differential между всеми 16 `u/e` направлениями. Дополнительно исходный отдельный A11 checker воспроизведён в изоляции: все 256 exported B21 raw u/U совпали, max ошибки `3.47e−18` / `0`; результат и hash — [A11_FRAME_REPLAY.json](A11_FRAME_REPLAY.json). Постоянный exterior-lift `R` сохраняет соответствующий полный CAR trace.

Исходные F2–F6 reference написаны для Cartesian `eta_C=diag(1,-1,-1,-1)` и **не** совпадают с установкой `e_ref∝I` в null-frame. Положим `T` с Hadamard-блоком `1/sqrt(2)*[[1,1],[1,-1]]` в индексах `0,1`, единицей в индексе 2 и `−1` в индексе 3. Точно `det T=+1`, `T eta_C T^T=eta_null`. Используем

```
e_ref,null = T (s_ref/sqrt(rho)) I,
U_ref,null = T U_ref,Cart T^T,
u_ref = nu sqrt(rho)/s_ref · T eta_C,
u_ref^T eta_null u_ref / nu² = rho/s_ref² · eta_C.
```

При `s_ref=6`, `h=1/4` исходные `A,B` — Cayley boost 02 и rotation 12 до этого переноса; одинаковые константные ссылки допустимы и на торе. `Psi_time=a_h(-1)^x0`, `Psi_space=a_h(-1)^x1`, scalar grade, `a_h=h s_ref sqrt(d_h)/2`, `d_h=F_h/(s_ref² k0)`. Их forward differences правильно дают `q_time=+rho d_h`, `q_space=−rho d_h`. [check_reference_frame.py](check_reference_frame.py) проверил точными алгебраическими равенствами frame и Lorentz, а исходным A11 polynomial DAG численно подтвердил `f_ref±=±F_h/36` и соответствующие знаки `q`, на одном reference site. Действительные банки требуют подготовки всех 256 sites, marks и указанного общего norm/compiler.

## 4. Независимая проверка интерфейса A11

[replay_a11.py](replay_a11.py) скопировал 6 файлов A11 во временную директорию **внутри round24**, выполнил три команды в изоляции и удалил временную копию; direct/round11 не изменялся. Все три regenerated JSON побайтно совпали с прочитанными оригиналами, hashes и полный stdout — в [A11_REPLAY.json](A11_REPLAY.json). Проверены `20 402` DAG nodes, `282` независимых scalar coordinates, 16 link operands, полный degree `[82,0]` и `[2,2]`, copy-bound `180 Choi + 16 CAR` на report, рациональный общепространственный majorant `Lambda_h=2^1525`, `epsilon_h=2^-1531` при `A≤4096`, `rho≥3712/5473`. Численное сравнение 282 derivatives с отдельными CAR-matrix формулами дало относительную ошибку `<5.3e−15`, для 160 normal directions `<5.4e−15`; одна оригинальная interior stencil равна нулю с численной точностью.

Это ограниченный replay и проверка семантики в рамках декларированного локального интерфейса. Он не строит seven-bank native processor/READY, не доказывает что физический history/C соответствует выбранной секции и не превращает расчетную норму в физически исполненную цену. A11 source `direct/round11/FULL_SOURCE_OPERATOR_RU.md` следует читать вместе с его собственными границами.
