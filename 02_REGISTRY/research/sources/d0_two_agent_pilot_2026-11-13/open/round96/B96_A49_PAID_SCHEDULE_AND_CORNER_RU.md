# B96: A49 paid padding, actual post и corner A27 на новых vertices

**Результат: PASS в заявленной typed области.** Проверены one-pass PadTo, CODE-control-only структура actual A48 core, конечный path-sum evaluator и четыре star lists на малых actual G/CX fixtures, 13 оплаченных slot arms и growing-clock формула. Независимо воспроизведены арифметика production padded bounds и перенос A27 семиотчётного moment law на новые значения поля. При закреплённых A27/B54 и A48 owners получаем для выбранного typed canonical RAW fibre `e_M<2^-3421<2^-3298` и `M_b>2/3` для всех CODE labels. Original `Dν`/marked admission и физический Cost−Info этим не установлены; `physical_C_closed=false`, `GR_closed=false`.

## 1. Реально оплаченный PadTo

[paid_padding.py](/Users/grigorijvahrusev/Downloads/d0_pilot_direct_2026-11-13/02_REGISTRY/research/sources/d0_two_agent_pilot_2026-11-13/direct/round49/paid_padding.py) обходит переданный stream один раз, считает действительные G/CX calls с учётом repeat-DAG и сохраняет tag на реально достигнутом месте. После окончания он исполняет `total−used` реальных CX из identity-слов длины 2 или 5; если исходная верхняя граница не оставляет требуемые четыре вызова, итератор останавливается с ошибкой. В [audit_paid_padding.py](audit_paid_padding.py) проверены длины 4–41, все восемь колонок трёх CODE wires, вложенный repeat, сохранение марки и отбраковка завышенного source. Незапущенный большой word не считается выполненным; exact новая длина условна успешному завершению finite stream и proof исходного upper.

В production A49 исходный A47 control уже имеет свою точную длину. К ней добавлены ещё 4 оплаченных CX на каждый из четырёх control slots: именно дополнительные 16 вызовов включены в `L_base`. Upper для старого unpadded core не переименовывается в его фактическую цену: новая padded длина равна upper+4 при завершении своего однопроходного подсчёта.

## 2. Actual диагональная компрессия и пост

[finite_actual_target.py](/Users/grigorijvahrusev/Downloads/d0_pilot_direct_2026-11-13/02_REGISTRY/research/sources/d0_two_agent_pilot_2026-11-13/direct/round49/finite_actual_target.py) суммирует действительно порождённые G/CX primitive paths и WORK RAW amplitudes для каждого CODE label, без массива состояния размера `2^n`. Повторный обход вычисляет именно фактический core, а не его идеальное отражение или готовую target table. Метод является конечным математическим алгоритмом; количество путей колоссально и production-запросы не выполнялись. Один path всё равно требует конечного WORK-index, число бит которого растёт с размером WORK: отсутствие массива `2^n` не является обещанием практической памяти/времени.

Первоначальный вызов A49 использовал `int.bit_count()` и падал на установленном Python 3.9.6. Владелец исправил его на `bin(n).count('1')`; проверена уже исправленная версия. [audit_actual_target.py](audit_actual_target.py) независимо сопоставляет все 8 CODE labels двух малых G/CX fixtures с exact Q4 state-vector calculation, включая повторения, смешанный WORK control и несортированные CODE addresses. CODE-targeting G отбраковывается. Для положительного малого actual M проверены 28 вызовов четырёх A41 star lists и одна реальная B80-selected степень; численная диагностика полученного целевого поста переводит `Mχ/||Mχ||` в χ с ошибкой `<2^-100`. Последняя диагностика не является интервальным доказательством production word.

Для giant core свойство «CODE только controls» не устанавливается одним fixture. [audit_code_support.py](audit_code_support.py) проверяет все 1 568 namespace bindings и отдельные constructor footprints: A19 prefix и adapter/gray targets — WORK; coframe и material targets/permutations — modes/flag/aux/grade; все шесть proper-link Fock mode pairs — WORK с CODE лишь в controls; SITE, REPORT ranges, SC6 и RAW resources не пересекают CODE. A29 SourceI/CZ lowering использует reserved старый WORK helper как target, даже если исходный CZ использует CODE как control. Проверены физическая injectivity и 4 214 coframe family/width classes. Вместе с закреплёнными B93/B94 grammar owners это структурный вывод о real CODE-control-only core, без перечисления `2^29` масок и развёртывания полного слова. Следовательно его canonical WORK compression M — реальная диагональ на полном CODE.

## 3. Четыре независимых слота и clock

[audit_four_slot_schedule.py](audit_four_slot_schedule.py) независимо строит все 13 малых centre/matched/`P_f,Q_f,Q_b,P_b`/post-probe endpoint histories. Они имеют одинаковую точную padded длину, один фиксированный post, обе source marks на одинаковых native layers и четыре независимых знаковых slots. Матчированная хронология `(+,-,+,-)` заканчивается `P_b†` до post; независимый probe после post отмечен как другая basis. Малый clock D получен прямым суммированием всех фактических ранних birth, body gate и retention dimensions, а не только сверкой формулы.

[audit_production_plan.py](audit_production_plan.py) повторно вычисляет целочисленные upper, резервы и exact padded length expressions A49: `N_base.bit_length=30833`, `K=175604`, m=5376 и m+ceil(m/2)=8064. Эти арифметические результаты не являются выполнением production schedule, проверкой всех оригинальных marks или доказательством stationary physical price.

## 4. A27 moment law на четырёхзначном поле и corner

Старый B21 asymmetric interval для каждой координаты — `[−p²·2^-30,p·2^-30]`; новые точки `2^-80(d−3p²)`, `d=0,1,2,3`, целиком внутри него, поскольку `3<2^50` и `1−p²=p`. B93/B94 покрывают новый полный четырёхзначный Julia/coframe/material catalogue на том же typed SOURCE. A27 §2 формулирует исходные Choi и CAR leaf identities для **всех** b, где эти цели определены: они являются алгебраическими identities состояний, а не interpolation по двум старым именам. Те же исходные copy offsets, общий PF SITE, REPORT и SC6 сохраняются.

[audit_corner_law.py](audit_corner_law.py) повторяет полный семиотчётный SC6 event polynomial на всех `4^7` конфигурациях READY/REPORT. Нормированный отдельный fresh A46 bank не меняет ideal endpoint: его идеальный закрытый REPORT D коммутирует с C и Z, хотя может **не** коммутировать с R через общий SITE. Независимый exact 4-qubit fixture проверяет именно это более слабое условие. Actual REPORT использует общий port/helper; его ошибку нельзя отменять как точную коммутативность, и она остаётся в A48 compressed error. Связанные с b полные источники и retained remainder не трассируются для иных marks или Q-вставок.

Следовательно при A27/B54 исходном product-moment law, правильном B93/B94 target binding и заявленном A48 canonical-input/compressed error

    M⁰_b=c_ref−2g Iτ(Y_b),    ||Mhat−diag_b(M⁰_b)|| <2^-3421,
    e_M <2^-3421 <2^-3298,
    M⁰_b>67/100,             2/3 < Mhat_b ≤1.

Второе неравенство использует exact CODE control-only структуру и сохранённый B54 probability lower bound, не численную выборку. Это снимает **математическую typed corner premise** для нового actual core и обеспечивает положительный `Mχ`/radius в A49 path evaluator. Оно не переопределяет исходные `Dν`, не устанавливает эквивалентность A23 unitary extension другому не предъявленному original vacuum prefix и не разрешает удалять текущие DATA или любые связанные failure/record факторы.

## 5. Same-reader gain и shared-bank price interface

[audit_price_bridge.py](audit_price_bridge.py) независимо воспроизводит A49 source-normalization bridge. Из исходного `c_ref=1−8κp^7`, `κ≤1`, `p^7=13p−8` и рациональной верхней границы p следует `c_ref>2/3`. Положительность всех `Mhat_b` даёт `r=||Mhatχ||>67/100−e_M`; один фиксированный пост с ошибкой `<2^-9247` сохраняет `c0hat>2/3`. При исходном Book reader, `η=z p^K`, `0<c0hat≤1` и отдельно подтверждённом `gσ>2^-3208` фактическая нормировка имеет

    Γ=4z p^K c_ref gσ/(1−z+z p^K c0hat²)
      >(8/3) z·2^-3208 p^K.

Оригинальные `g` и reader не переопределяются. Для одного и того же SOURCE в ± плечах ранее доказанное B95 сокращение и реальные A47 control errors дают нормированный **локальный operator interface** `<2^-189`. Он не является вычислением всех физических Cost−Info sources, original marks или полного eM-составного price gradient.
