## 1. Реальная архивная поддержка и текущий глобальный bound

Буквальный copy-word сохраняет шесть сырых битов `(r,t,r,t,t,r)`. Для честного valid вывода существуют ровно

```
S0: 00/000000, 01/010110;
S1: 10/101001.
```

Все другие carrier columns, в том числе invalid и несогласованные copies, остаются, но не входят в initialized output выбранного truthful reader. Born amplitude на исходных восьми битах равны `p^4,p^6,p^6`, следовательно на исходном неизвестном input

```
j* S0 j=(p^8+p^12)I=mu0 I,
j* S1 j=p^12 I=mu1 I.
```

Для любого complete current изометрического конкурента, который сохраняет именно эту поддержку и scalar coarse effects `(1−q)I,qI`, Cauchy–Schwarz даёт all-input

```
C*C ≤ [sqrt(mu0(1−q))+sqrt(mu1 q)]² I.
```

Это верно и для комплексных конкурентов, а не лишь для одного вещественного угла. Нормированная яркая целевая пара коэффициентов равна `(1,p²)/sqrt(1+p^4)`, поэтому `u_J=p^4/(1+p^4)`. Нормированный dark target задан `10/101001`. Если физическая задача допускает восстановление перед reader и не фиксирует по отдельности исходные тонкие эффекты, эти две цели являются математически достижимым равенством в bound. Обратный знак/фаза не дают лучший максимум. Сохранение прежнего `K_invalid=0` требует реальной линейной support-реакции, не только вырождения квадратичного эффекта.

## 2. Уточнение достижимости и every-competitor предпосылки

**Scalar effect сам по себе не обеспечивает доступного WORK-only восстановления.** Например, для `L*=−L`, `L²=−I` изометрия `K=(|0>⊗I+|1>⊗L)/sqrt(2)` имеет `K*K=I`, но у неё нет WORK-only унитарного преобразования к `|j>⊗I`: ненулевой коэффициент при линейно независимом Spin-операторе `L` невозможно обнулить унитарным вращением WORK. Это математический контроль границы, а не утверждение, что выбранный реальный H.1 centre имеет такой вид.

Владелец LC10–LC11 отдельно доказывает для **выбранных буквальных identity-preparation EO/NPS centres** свойство `K_b=w_b⊗I_Spin` с real `w_b` на всех колонках. Для этого centre real sector-preserving SO compiler и оплаченные helpers дают необходимую условную аппроксимацию новых целей; остальные комплексные конкуренты покрыты верхней оценкой, но не обязаны сами быть центрами компиляции. Поэтому наиболее точная формулировка достижимости A9: **при этом real-`I_Spin` centre либо при отдельно доказанном физически допустимом Spin-coupled recovery**, с фиксированной ареной, прежними marks и их допустимым транспортом. A9 ссылается на все условия LC1–LC11; этот пункт должен оставаться явным при любом дальнейшем переносе и не может быть заменён одним `E_b=q_b I`.

Аналогично перенос current optimum на произвольный предыдущий prefix требует **для каждого сравниваемого конкурента**, а не только на optimum: старый WORK пассивен, единственный source apparatus действительно восстановлен оплаченной handoff, native профиль один и тот же, все новые births и носители retained, и операторы не обращаются к sealed oldRIGHT. Тогда действительно `C_total=C_current C_<`; при условии owned Spin-only алгебры `C_<*C_<=k_<²I` обычная оценка сохраняется после домножения. Произвольный mutable DATA, дополнительные Spin axes или самостоятельные old-prefix операции не включены автоматически. Ни A9, ни этот review не строят реальный полный H.1 recovery/список всех mark-reader transports.

## 3. Gain, старые строки и дополнительная цена

При перечисленных условиях новый полный когерентный возврат равен

```
f_arch(q)=sqrt(p^8+p^12)sqrt(1−q)+p^6 sqrt(q).
```

Его стационарная coarse вероятность равна `p^4/(1+2p^4)<p²`, поэтому на `p²≤q≤1/2` имеем `f_arch>0`, `f'_arch<0`, `ell_arch=−f'_arch/f_arch>0`. `f''<0` делает `ell_arch` строго возрастающей; значения концов в A9 согласуются с независимой подстановкой.

Для M повторов, только при восстановленной scalar factorization всех конкурентов и независимых исходных preparation slots,

```
s=product_i f_arch(q_i)^2,
w=r z k_old² s/(1−z+z k_old² s),
Gamma_J=2w sum_i ell_arch(q_i) g_i.
```

Экспоненциальное ослабление `s` остаётся в фактическом gain; сокращение допустимо в приведённом отношении old-row/gain при `k_old²>0` и настоящем bound на весь `D_old A`. Тестовый `Gamma_J≈1.59915·10^-38` при `M=20` подтверждён, но относится лишь к числовому fixture checker. Для разных независимых слотов right lift следует понимать на product-input, как одновременный lift всех нужных компонент, а не как склейку их вариаций.

Совпадение с отдельно заданной A8 fine-code/CQ ценой верно: в `u_J` её независимая строка `(1−q)(1−4a)` равна нулю только при `a=bQ+bC=1/4`. Если такая цена действительно прибавляется к полному физическому operand при других коэффициентах, оптимум одного `J` не решает joint instrument row. Само равенство `1/4` не выбирает физическую Info и не доказывает, что measured CQ и исходный unitary clock относятся к одному execution.

## 4. Clock и правильное полное завершение

При буквальном layout без дополнительных рождений: 36 echo calls, 6 births, 102 zero-prep calls, 30 delivery calls, всего `174` стадии; `d_final=64d`, `D=D_<+8547d`, birth ages `(137,136,135,134,133,132)`, `L=132`. Истинный последний gate — `CX(port,t)`. Вставка `N_rec` calls на прежней `d`-арене **до шести рождений** и `m` двух-call padding pairs после последнего рождения даёт `D=D_<+(8547+N_rec+128m)d`, `L=132+2m`. Рождения helpers вне указанного prefix, другие late births, measured controller или остановленное дерево требуют нового layout.

Для полного растущего clock используется `W_can=Σ_j U_(j,f)D_j B_(j,f)*` с фактическими birth-detail пространствами, а не raw word, тензорно продолженный на ранее не существовавшие носители. Локальные fixture checker действительно показывают, что наивное продолжение даёт другой winding polynomial. Эти три модели конечномерны и численны; identity применяется к большому writer по исходной общей теореме, не по сборке полной матрицы H.1.

Оценка исходной full two-degree heat сцены при `beta=2p²` — `A_132≤4.47361453917822·10^-415`; rational inequality проверена точно. Нормированная ошибка есть `A_132 C_full/Gamma_hat`, а не просто `A_132`; конечные слова также платят настоящий comparison step, все occurrences, basis/right-lift norms и фактические reader/other ledger rows. Повторяемый physical gain может быть очень мал. Теорема применима к сохранённому **unitary** архиву; внешний CP/dephasing требует своей дилатации, clock и cut. Используемый native `report_bits` — metadata и измерительный прибор не реализует.
