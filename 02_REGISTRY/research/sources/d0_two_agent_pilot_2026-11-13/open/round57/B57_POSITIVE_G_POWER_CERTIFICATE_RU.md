# B57. Положительные степени G для новых Z/CZ gadgets

Для четырёх вращений B56 построен общий положительный показатель `k`. Проверяются **фактические** `2k,14k,4k,12k`, а не только исходный `k`. Углы и оценки — по существующей матрице `G=[[sqrt(p),−p],[p,sqrt(p)]]`, `p=(sqrt(5)−1)/2`.

| Показатель | Идеальная цель | Строгая операторная ошибка |
|---|---|---|
| `2k` | `R(+pi/4)` | `<2^-7456` |
| `14k` | `R(−pi/4)` | `<2^-7453` |
| `4k` | `R(+pi/2)` | `<2^-7455` |
| `12k` | `R(−pi/2)` | `<2^-7454` |

Все показатели положительны. Точное целое `k`, hex границы вещественной и мнимой частей для каждого фактического показателя, числители строгих оценок нормы, масштаб и hashes хранятся в [GADGET_G_POWER_CERTIFICATE.json](GADGET_G_POWER_CERTIFICATE.json). [Проверочный скрипт](certify_gadget_g_powers.py) не пишет в файлы A14. [Быстрая проверка](verify_certificate_output.py) отдельно сверяет hashes, показатели и записанные арифметические неравенства; она не повторяет трудоёмкое возведение в степень.

Кандидат предложен `candidate(7440)` владельца A14. Численный поиск сам по себе не является доказательством. Два независимых пути дальнейшей проверки используют только целочисленные квадратные корни, интервальные операции с округлением наружу и возведение в фактическую целую степень: один сначала получает интервалы для `G^k` и строит по ним четыре кратных, другой отдельно вызывает исходный owner interval evaluator для каждого `G^(m k)`. На обоих путях сверяется строгое неравенство `<2^-7432`. Для `±sqrt(1/2)`, `0` и `±1` целевые интервалы строятся целочисленно; π и числа с плавающей точкой в сертификате не используются. Операторная норма ошибки ортогональных вращений ограничена суммой ошибок косинуса и синуса.

Первый расчёт при 15136 битах дал слишком широкий, хотя корректный interval bound и не прошёл требуемый порог. Окончательный проверочный расчёт использует 18000 бит: это учитывает раздувание прямоугольных интервалов при 7456-битном показателе. Неуспешный промежуточный bound не входит в утверждение сертификата.

Если отдельный компилятор полностью покроет исходные макросы без пересечений, каждая новая замена использует не более четырёх таких вращений, а число замен не превосходит числа букв `L` исходного A25 W с `L<2^4188`, то гибридное all-column неравенство даёт суммарную ошибку `<L·4·2^-7432<2^-3242`. Это **условная** оценка компоновки, не доказательство существования или полноты такого компилятора. Один helper может переиспользоваться при all-column оценке; его действительное рождение и цена должны входить в новую историю.

Утверждений о сохранении старых отметок, старой цены, физическом допуске, закрытии Cost−Info или ОТО здесь нет. `physical_C_closed=false`, `GR_closed=false`.
