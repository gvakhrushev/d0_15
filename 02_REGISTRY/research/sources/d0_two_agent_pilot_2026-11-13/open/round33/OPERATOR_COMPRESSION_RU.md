# B33. Операторная компрессия исходного source controller

## Точная формулировка и граница

Пусть `D_x` — полное тензорное пространство всех Choi/CAR copies A11, включая неиспользуемые колонки и spectator RIGHT, а SITE — один общий внешний управляющий регистр. Исходный input на `SITE ⊗ D ⊗ R` может быть произвольным и запутанным с внешним `R`. Предполагаются независимые fresh ресурсы B31/A13, чистый рабочий вход A15 и **реальный selected-leaf consumer**, точно реализующий контракт ниже на фактических выданных инструкциях. В идеальной логической модели компрессия совместно готового controller равна

```
W† Π S_kind Π W = Q · Σ_x |x><x|_SITE ⊗ [ H_kind,before-PF(x) / (rho_x Lambda_h) ] ⊗ I_R.
W† Π W = Q I.
```

Здесь `W` — физическая изометрия полного приготовления fair banks и выполнения selector/controller до выбранного контролируемого source-оператора, `Π` проверяет соответствующие сохранённые READY, `S_kind` применяет по инструкции подписанные инволюции и знаки к выбранным физическим копиям, `Q>0` — готовность **именно включённых** banks/slots. Обозначение `W†` задаёт математическую компрессию; оно не предполагает бесплатного физического обратного прохода. Если consumer исполняется сразу после выдачи каждой инструкции, перенести его в конец для этого доказательства можно лишь при доказанном сохранении SITE, всех прежних records, selector-input wires, δ и будущего READY; при этом действия на source-копиях коммутируют с дальнейшим вычислением инструкций, а отдельные знаки умножаются. Любой gate, меняющий такие управляющие регистры или потребляющий чужой δ, нарушает эту перестановку. Если включены все fair banks и все ten-sign slots одного report, то

```
Q = q28^10248262 · r_t^10 · r_i^1054,
q28=1-(1-2p^3)^28,  r_t=1-(1-tau_t)^7,  r_i=1-(1-tau_i)^7.
```

`Q` относится к одному условному instruction preprocessor. Для семи независимых подготовок их общая готовность равна `Q^7`; отождествления с полной H.1 `alpha_h` нет. Выше — операторное равенство по всем source columns, а не утверждение только о средних на правильно приготовленных источниках. Если consumer ещё не реализован и не соединён с A15, это теорема с явно названной открытой предпосылкой, а не результат запуска полного native word.

## 1. Лист и реальная инструкция

Для `a≠b`, `m(x)=[x=a] XOR [x=b]`, `h,delta∈{0,1}` положим

```
|x> -> (-1)^[h delta (1-m(x))] |x XOR [h m(x) (a XOR b)]>.
```

При `h=0` это identity; при `h=1` и `delta=0` получается swap `T_ab`, при `delta=1` — swap на паре и `-I` на её дополнении. `m` сохраняется при swap, потому что swap только меняет местами `a,b`. Поэтому map является инволюцией; адреса `a,b`, SITE, delta, records и все чужие copies не должны меняться, clean work должен быть восстановлен. На полном carrier, включая spectator RIGHT,

```
V0=T_ab, V1=-Z_a Z_b T_ab,   (V0+V1)/2 = |a><b|+|b><a|.
```

Настоящие A11 leaf множители — `16 A`, `32 A` или `1` с `A=2049`; они входят в массу leaf, не применяются повторно к инволюции. Проверены все 72 192 адресных записи A15, включая 2 560 CAR с ненулевым `a`; для них `a≠b`. `ACTUAL_LEAF_CONSUMER_SPEC_CHECK.json` проверяет 1 459 160 representative значений `x,h,delta`. Произвольная колонка относится к одному из трёх классов `x=a`, `x=b`, `x` вне пары, что завершает all-column доказательство логической спецификации. Проверка не исполняет ещё не предоставленный A16 gate stream. Независимый `check_dynamic_pair_gates.py` строит реальный логический word X/CX/CCX/CZ для произвольной ширины: оба equality scratch очищаются до swap, затем инвариант `m` пересчитывается для очистки. Исчерпаны 17 360 допустимых колонок при ширине 1–4; 22-битный word отдельно исполнен на 4 800 случаях по 400 настоящим парам, включая CAR. Это самостоятельный witness одной выбранной пары, не copy-router и не native word A16.

## 2. Свежий delta на физическую копию

Для каждой Choi/CAR physical copy выделен свой fair `delta`. При B31 READY весь payload ровно равен `|+>^M`, факторизован от сохранённых fair-bank histories; δ не используется для выбора ветви или palette. Следовательно условно на любую selector history эти δ независимы. B32 независимо проверил A15 offsets: в mul поддиапазоны детей не пересекаются, в add посещается один ребёнок, в дополнении стоят identity. Значит на одном выполненном пути каждая физическая copy адресуется не более одного раза; один и тот же δ этой copy допустимо применять в альтернативных взаимоисключающих путях. Разные физические copies не могут разделять один δ. Пример на complement `|2,2>`: общий δ для двух `X_01` даёт `E[V_delta⊗V_delta]=1`, а независимые δ дают `(X_01⊗X_01)|2,2>=0`.

Это правило не предполагает независимости входных Choi/CAR состояний: независимы только свежие управляющие ресурсы. На произвольном, даже запутанном, входе среднее tensor-продукта независимых контролируемых инволюций равно tensor-продукту операторных средних.

## 3. First success с сохранённой историей

Для palette `j` одна попытка возвращает метку `l` с весом `tau w_jl` и abort с весом `1-tau`, причём один и тот же `tau` действует для каждого coherent `j`. При семи отдельных попытках вероятность того, что **первая** успешная имеет метку `l`, равна

```
Σ_(t=0..6) (1-tau)^t tau w_jl = [1-(1-tau)^7] w_jl.
```

Все семь raw inputs, labels, failures, unused suffix и records сохраняются. Последующие attempts исполняются и после первого успеха; они не меняют выбранную метку. Разные истории ортогональны как basis states сохранённых registers, поэтому в компрессии возникает диагональная по histories сумма весов, без предположения одинакового garbage при разных `j`. Свежие ресурсы следующего slot независимы от прошлой истории, а общий `r=1-(1-tau)^7` не зависит от `j`; поэтому последовательное условие всех фиксированных slots даёт скаляр `r^slots I`, даже когда выборы адаптивны и SITE когерентен. Dummy slots имеют тот же `r` и не пропускаются.

Независимый `check_exact_dag_compression_inputs.py` восстановил в точной Q(p)-арифметике все 20 402 массы и bidegrees, 3 618 reachable add palettes, 25 внутренних palettes и 512 SITE×kind top palettes; для каждой строки проверены exact `tau w` и abort. B31 даёт такое же отделение fair payload от retained fair history на совместном fair READY; failure-ветви в полной схеме не удаляются.

## 4. Индукция по DAG и общий SITE

Для каждого ненулевого узла положим `m(const)=|c|`, `m(leaf)=leaf multiplier`, `m(add)=Σ m(child)`, `m(mul)=Π m(child)`. Пусть `K_i` — средний selected operator данного узла после успешных фиксированных slots:

* `const`: сохранённый знак даёт `K_i=sign(c) I=H_i/m_i`.
* `leaf`: независимый δ и равенство раздела 1 дают `K_i=H_i/m_i` на полном carrier.
* `add`: с вероятностью `m_j/m_i` выбран child `j`; он занимает начальные offsets родителя, прочие copies — identity. Следовательно `K_i=Σ_j (m_j/m_i)(H_j/m_j)⊗I=H_i/m_i`, включая identity padding.
* `mul`: A15 выдаёт все children и смещает отдельно Choi/CAR на суммы bidegrees предыдущих детей. Их интервалы и свежие δ не пересекаются; индукция даёт `K_i=⊗_j(H_j/m_j)=H_i/m_i`. Повторный индекс DAG на другом физическом offset не означает повторное использование неизвестной copy.

Для top palette при фиксированных `x,kind` A12 задаёт `w=m_root/(rho_x Lambda_h)` и веса `(1-w)/2` для `+I,-I`. Их вклады сокращаются, так что итог `w H_root/m_root=H_root/(rho_x Lambda_h)`. Обнулённая top identity-ветвь проходит оставшиеся dummy slots и не обращается к leaf. Все поля `site` во всех десяти walk должны быть alias одного внешнего SITE; A15 предоставляет интерфейсы отдельных walks, фактический общий assembler обязан это соединить.

Поскольку controller и consumer сохраняют SITE, все формулы одновременно складываются в оператор, диагональный по SITE. Равенство на блоках даёт равенство на полном `SITE⊗D⊗R`, включая входы с межсайтовыми когерентностями и корреляциями с `R`; оно не требует, чтобы сохраняемые окружения для разных SITE были одинаковыми. Проверяется именно наблюдаемый/сжатый оператор, а не утверждается сохранение межсайтовой когерентности после трассирования всех histories.

## 5. Нужен ли обратный проход приготовления?

Для самого Hadamard-измерения достаточно приготовить `|+>_h`, выполнить conditional consumer `|0><0|⊗I + |1><1|⊗S_kind`, затем измерить X на `h`, сохраняя histories и проверяя тот же READY. Поскольку `S_kind` оставляет READY и histories неизменными, на ideal input получаются точные joint effects

```
E_(±,READY) = Q/2 · (I ± O_kind),
O_kind = Σ_x |x><x| ⊗ H_kind,before-PF(x)/(rho_x Lambda_h).
```

Математическое `W†` появляется при вычислении эффектов и **не обязано исполняться физически** ради такой статистики. Если другая часть H.1 требует чистый возвращённый ancilla, конкретный канал после результата, coherent block encoding или marked inverse, это отдельный контракт: один правильный POVM effect не доказывает нужный post-measurement instrument. Даже буквальный `W^-1` сам по себе не гарантирует, что все histories после data-dependent SELECT детерминированно вернутся в исходное состояние; это требует отдельной проверки и оплаты.

## 6. Проверка и оставшиеся обязательства

`COHERENT_TOY_CHECK.json` даёт полную малую 18×18 operator проверку с двумя SITE, retained histories, identity padding, знаками, отдельными δ и произвольным coherent input, запутанным с внешним регистром. Для cap7 отдельно перебраны все 16 384 истории; по 5 461 относятся к каждой из трёх успешных меток, одна — к abort. Это диагностический конечный пример, не замена индукции по настоящему DAG и не запуск A16.

Условие конкретной реализации consumer включает правильный selection copy по A15 offsets, conditional sign на `h`, сохранение всех records/READY/SITE/δ, clean scratch и отсутствие обращений к protected RIGHT. Соответствие фактического A16 этим условиям и его native forward/literal inverse должны быть проверены на текущем коде. Ошибки A13/A14/A15/B31 условно ограничивают уже известные части, но не включают новый consumer, births, marks и полный clock; при приближённых gates exact scalar READY и exact равенство компрессии автоматически не следуют. Полный H.1 `alpha_h`, physical Cost−Info и GR остаются открыты: `physical_C_closed=false`, `GR_closed=false`.
