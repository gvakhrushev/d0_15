# B29. Ошибка полного H.1 writer и условный численный бюджет

**Результат:** при явной, пока недоказанной предпосылке `alpha_target >= 1/2` для **полного идеального** ten-sign reporter, исходный owner даёт на выбранном `L=4`, `A=2049`, `Lambda_h=2^1525`, `s=2^-30` строгие оценки

```
g > 2^-3128,                 g s > 2^-3158.
```

При фиксированном каноническом initial embedding и полноколоночной ошибке полного forward writer `eta <= 2^-3169` получаем `e_B <= 2 eta <= 2^-3168` и член `e_B/(g s) < 2^-10` в T10 **на единицу нормы генератора X**. Это только один из членов полной оценки. Для вывода по координатам нужен правильный lift, включая фактор нормы и фактическую геометрическую карту; для полного native writer и его отмеченной истории ещё не составлены counts и error ledger. Сама гипотеза о полной `alpha_target` не следует из одного `alpha_component>=1/2` A12. `GR_closed=false`.

[certify_error_budget.py](certify_error_budget.py) содержит рациональные и outward-interval проверки всех указанных чисел. Ниже явно разделены target-предпосылки, ошибки compiled word и пока неизвестные физические коэффициенты.

## 1. Как ошибка стадий входит в T7

Используем именно owner §7eh.H.1–H.4, T1–T10. Пусть `A` — **полный идеальный** `b`-controlled геометрический writer, включая настоящий SITE, семь настоящих bank preparations, selectors/READY/reports и comparator; `A_hat` — один фиксированный реализованный word на том же каноническом born graph. В предпосылках T7

```
||A_hat−A||_op <= eta_A,
W=A* Z_report A,             W_hat=A_hat* Z_report A_hat,
M=j_W* W j_W,                M_hat=j_W* W_hat j_W,
||M_hat−M|| <= 2 eta_A = e_B.                         (1)
```

При одинаковой `j_W` это простая телескопия двух множителей и `||Z_report||=1`. Сравнение должно быть **all-column** на полном пространстве всех принадлежащих word ресурсных и вспомогательных колонок, а не на выбранной готовой ветви, только на вероятности `q` или только на `|0>` вспомогательных проводах. Для растущего носителя каждая стадия сравнивается как isometry между соответствующими настоящими входным и выходным fibres; ранние пространства нельзя неявно дополнить будущими проводами и объявить такую стоимость фактической.

Если отдельно сближать реальный initial embedding и reader, а не включать их подготовку внутрь `A`, то безопасная оценка при одинаковом пространстве и isometric maps:

```
e_B <= 2 eta_A + 2 eta_j + xi_report,
||j_hat−j|| <= eta_j,    ||Z_hat−Z|| <= xi_report.    (2)
```

Но изменение канонического checkpoint не объявляется автоматическим допустимым H.1: (2) только norm-bound, а необходимые точные структурные свойства ниже всё равно надо проверить. Если физический backward word **буквально платный inverse фактического** `A_hat`, в (1) не нужно ещё раз добавлять `eta_A` сверх множителя 2; cost при этом включает все gates обоих проходов. Если backward приближается независимым word `B_hat`, telescoping даёт `eta_forward+eta_backward`, однако `B_hat Z A_hat` не обязан быть Hermitian reflection — T8–T10 тогда не перенесены без отдельного доказательства. Каждый внутренний inverse, встречающийся уже **внутри** forward `A`, считается отдельным вхождением в `eta_A` и в цене.

Для фиксированной последовательности `A=A_N...A_1`, фактических isometries или unitaries нормы 1 и единых stage-fibres,

```
eta_A <= sum_{occurrences k in A} ||A_hat_k−A_k||
        <= N_X d_X + N_CCX d_CCX + N_H d_H
           + sum_other_occurrences d_k + eta_banks + eta_SITE + eta_other. (3)
```

Это bound суммы по **реальным вхождениям**, а не по различным gate types. В него входят всё необходимое: все копии, reruns, fixed padding, подготовленные ресурсы и ошибочные реализации их inverse, conditional wrappers и любой дополнительно требуемый unsplit current mark. Ошибку одного compiled macro можно учитывать одним all-column bound либо суммой ошибок его внутренних подслов, но не забывать их и не считать дважды. Если native `G/CX/SourceI` идеализированы как точные допустимые gates, в цену входят все их вызовы, но лишняя approximation-error на каждый такой вызов не вводится; если моделируется погрешность аппаратных primitives, для неё необходим отдельный budget на **все** actual native occurrences, включая outer paid reverse и padding.

Gate/copy counts должны относиться к одному уже зафиксированному ideal logical schedule и к тем же носителям/marks, что исполняемый физический word. Для gate под управлением SAM/SITE подставляется norm-error **действительно скомпилированной управляемой версии** на полном пространстве controls, auxiliaries, port и Spin; допуск только на её неконтролируемый target без доказательства wrapper не переносится автоматически. Если число логических замен, подготовок или обратных вызовов ещё неизвестно, его нельзя подменить счётом A13. Длина раскрытых native approximants может зависеть от требуемой точности; конечный total clock и соответствующие права/метки не следуют из (3).

## 2. Одна точная alpha в target и реальный scalar corner

Для T3–T5 идеальный полный reporter должен иметь одну field-independent `alpha_target>0`, общую для семи вызовов, и исходный закон `P_j=alpha_target r_j`. Она входит в `g`. `alpha_component` A12 относится лишь к selectors и fair-bank; равенство `alpha_target=alpha_component` или нижняя граница `1/2` для полного reporter требуют доказать, что **все** остальные ideal components детерминированы, полные fair/payload/DAG routing и preparation реализованы, а общий READY predicate не добавляет других success факторов. Дополнительный независимый ready-factor `1/2` уже превратил бы component `1/2` в полный `1/4`.

Приближённый физический word **не обязан** иметь свою точно равную, field-independent или вообще скалярную `alpha_hat`, чтобы пользоваться сравнением с таким идеальным target. При доказанном all-column `(1)` его отклонение от идеального эффекта, включая отклонение READY, поглощается в `e_B`; для отдельного READY projector на настоящем prefix требуются тот prefix и его собственное `eta_t`. Так, вероятности READY на любом нормированном input отличаются не более чем на `2 eta_t`, но это не делает их одинаковыми и не определяет точный физический gain через `alpha_hat`.

**Однако** малая норма сама по себе не даёт точную структуру owner T6. Для T9–T10 надо отдельно обеспечить, что фактический core сохраняет `Pi_b` и полный защищённый input как identity на требуемых границах, а именно

```
M_hat = sum_b c_hat_b Pi_b tensor I_D,
c_hat = i* M_hat i > 0                 is an ACTUAL scalar.
```

SAM остаётся control-only согласно владельцу; `B_R` действует только на resource banks, не на SAM, SITE, output labels, unknown `D` или oldRIGHT. Если конкретное раскрытие native gates временно меняет запрещённый SAM или защищённые факторы, одного endpoint-norm estimate недостаточно для приёма того же marked graph: нужен отдельный допуск и доказательство required marks. При нарушении окончательной T6 factorization простое равенство T9 с scalar `c_hat` не установлено.

[check_structural_boundary.py](check_structural_boundary.py) демонстрирует это на конечном hostile-контроле: `M_hat=cI+0.01 X_SAM tensor Z_D` находится на расстоянии 0.01 от скалярного `M=cI` и допускает обычную reflection dilation, но после сжатия точным `v` даёт две разные eigenvalues. Аналогично `diag(.51,.49)` близок к `0.5I`, однако это не один точный READY scalar. Контроль не утверждает, что конкретный A14 нарушает структуру; он показывает, что она не следует только из norm-error.

После отдельной проверки T6 используются **фактические**, а не target, величины owner T9:

```
A_old=C_< C_<*,      D0=(1−z)I+z p^K c_hat² A_old,
rho=A_old D0^-1 / Tr(A_old D0^-1),
w_hat=z p^K c_hat² Tr(A_old D0^-1)>0,
Gamma_s=4 w_hat g s/c_hat.
```

При `A_old != 0`, `c_hat>0` это определяет положительные `rho,w_hat`; их численная нижняя граница и физический `Gamma_s` без настоящего `A_old,K,c_hat` здесь не вычислены. Для нашего tiny `e_B` из owner `c_target>=1−12κ9 p^7` и `p<619/1000` следует `c_hat>13/25−e_B>1/2`, **если** этот `c_hat` действительно существует как scalar. Нельзя подставлять `w=1` или заменить его hypothetical readiness.

## 3. Численный условный gain floor

По B21/B25 и §7eh.B.3–B.4, для выбранных reference fields

```
epsilon_h=2^-1531,      delta_h=epsilon_h d_h,
d_h=F_h/(36 k0),         F_h=16517734400/162621047169,
g=2 kappa_9 p^7 d_h epsilon_h² alpha_target² r_x(0,0) r_y(0,0).
```

Именно **две** степени `epsilon_h` возникают из `delta_h epsilon_h`; `s=2^-30` появляется ещё раз в T10. В исходном nine-control слове `kappa_9=sin²(512 theta_G)`, `sin(theta_G)=p`. Interval evaluator использует точную рекурсию для `(sqrt(p)+i p)^512`, не float-inverse-sine; `r_x,r_y,k0` вычислены через исходный report law. При `alpha_target>=1/2` и `chi_h=1` он доказывает

```
2 kappa_9 p^7 d_h r_x r_y /4 > 2^-66,
g>2^-3128,       g s>2^-3158.                           (4)
```

Для ориентира, не как отдельная точная сертификация, `log2(g)` при `alpha_target=1/2` около `−3127.6948`, `log2(g s)` около `−3157.6948`. Если `alpha_target` меньше 1/2, floor в (4) недействителен; следует использовать фактический доказанный положительный lower bound и его **квадрат**. Если полная alpha вообще не установлена, численный floor условен и не является результатом физических вычислений.

## 4. Конкретный бюджет A13 и ещё неучтённые слова

A13 даёт на **один** ten-sign report логические decoder/label-routing counts

```
X=3 776 997 052;     CCX=9 403 481 772;     CX=9 400 485 374.
```

Если в одном forward `A` реально присутствует по одному такому fixed report для каждого из семи исходных вызовов, получается известная часть

```
N_X=26 438 979 364,      N_CCX=65 824 372 404,
N_X+N_CCX=92 263 351 768 < 2^37,
N_CX=65 803 397 618.                                  (5)
```

`CX` точен как разрешённый native primitive при имеющемся routing; физическая цена остаётся. Это не total `A`: отдельно отсутствуют полный source-DAG stack/offset dispatch, quantum/fair payload routes, подготовка 1 372 возможных источников, H tests, dynamic lookup, обрамление контроля, фактические marks/seal, всякие дополнительные вызовы и может понадобиться unsplit current mark. Другие копии/инверсии этого decoder также прибавляются к `N_X,N_CCX`, если оказываются в **forward** writer. Семь counted экземпляров, равенство каждого действительному A13 и весь remaining schedule ещё подлежат проверке.

При условии (4) три наглядных **достаточных**, не оптимальных распределения (все реальные остальные ошибки должны уместиться в резерв):

| Область гарантии для native-члена | `eta_A` | `e_B` | uniform bound каждого из (5) X/CCX | резерв всех остальных ошибок |
|---|---:|---:|---:|---:|
| T10 при `||X||<=1` | `2^-3169` | `2^-3168` | `2^-3207` | `2^-3170` |
| после owner scaled-chart lift `||X||<55` | `2^-3175` | `2^-3174` | `2^-3213` | `2^-3176` |
| после owner unit-physical lift `||X||<55/s` | `2^-3205` | `2^-3204` | `2^-3243` | `2^-3206` |

В каждой строке известный вклад из (5) строго меньше половины `eta_A`, поскольку `(N_X+N_CCX)<2^37`; вся остальная сумма обязана быть не больше второй половины. Тогда соответствующий native error после указанной нормы lift `<2^-10`. Это **не** оценка всей правой части T10 и не доказательство что compiled schedule достиг указанных tolerance. Если для будущего controlled-CCX установлен full-space bound `d_CCX<=3|Delta_angle|`, то в трёх строках достаточно соответственно `|Delta_angle|<=2^-3207/3`, `2^-3213/3` или `2^-3243/3`, при доказанном контроле всех вспомогательных/spin columns. Для X/H нужны собственные соответствующие bounds.

Root сообщает candidate A14 с bound `2^-4096` на каждый X/H/CCX; **если** конкретный проверенный word на всех нужных пространствах и состояниях действительно достигнет этого bound и остальные условия выполнятся, вклад только известных X+CCX из (5) `<2^-4059`, значительно ниже даже физического резерва `2^-3206`. Здесь A14 не проверен, и это сравнение не оплачивает его фактическую длину или отсутствующие слова.

## 5. T10, lift, 42 строки и отдельные marks

Owner T10 для допустимого подготовительного генератора X даёт

```
| DJ[X]/Gamma_s − DI_tau(Y0)[L_rho X] |
    <= [ L s R_v² + e_B/(g s) ] ||X||,
R_v²=p² m,      m=2688.                                 (6)
```

Только второй член ограничен предыдущими таблицами. `L >= ||D² I_tau||` на всём кубе здесь не вычислен. Например, **дополнительного** `L<=1000` достаточно, чтобы `L s R_v²<2^-10` на единицу `||X||`; вместе с первой строкой таблицы тогда вся правая часть `<2^-9 ||X||`. После scaled-chart lift `<55` более сильного `L<=10` достаточно для отдельного Taylor-члена `<2^-10`; ни одна из этих оценок `L` не установлена. Для unit physical displacement owner даёт bound `<55/s` на норму lift: не надо вставлять второй `1/s` внутрь самого `e_B/(g s)` — он появляется только при выборе соответствующего `X` в `(6)`.

В H.5 владелец получает для идеальных product SAM rotations `L_rho J_j=u e_j`, `u=2p sqrt(p)`. Точные неравенства `p>309/500`, `sqrt(p)>39/50`, `sqrt(2688)<52` дают `sqrt(m)/u<55` для scaled координат и `<55/s` для unit physical displacement. Однако фактический геометрический decoder и его Neumann correction добавляют собственный norm/condition number и ошибку `O(C_h s+C_h eta_mark/s)`; они не выданы одним числом здесь. Выше предполагается именно этот ideal right lift, а не бесплатный физический reader.

Нельзя переносить tolerance с 42 направлений одной точки на 2 688 координат или наоборот только потому, что `2688=64·42`: нужны фактическая карта полей/граничных строк, gauge, нормы её Jacobian и обратного lift, отмеченный decoder и значения `L,C_h,E_tau`. Для любой заявленной физической строки нужен собственный допустимый `X_r` либо оценка norm/right-inverse и суммирование связанных ошибок. T10 касается подготовительных generators на SAM/допущенных факторах; она не объявляет ошибки внутренних gate или свежего bank checkpoint source-neutral.

Для **каждой** необходимой отмеченной стадии t, с отдельным идеальным и фактическим prefix и observable,

```
||A_hat_t−A_t|| <= eta_t,   ||O_hat_t−O_t|| <= xi_t,
mark_error_t <= 2 ||O_t|| (eta_t+eta_j) + xi_t.          (7)
```

`eta_j=0`, когда фактический owner checkpoint фиксирован и все подготовки включены в prefix. Все реальные gates до этой конкретной стадии входят в `eta_t`, включая рождения, контролируемые компиляции, inverses и reader transport; endpoint `eta_A` автоматически не сертифицирует промежуточный mark. Если нужен общий aggregate error, суммировать соответствующие требования в выбранной норме, а не выдавать каждый локальный budget за полный.

Только как пример масштаба: у A=2049 raw Choi moment `||H_coframe||=16A=32784`, link moment `||H_link||=32A=65568<2^17`. Для отдельно объявленной absolute mark tolerance `2^-3168` достаточно `eta_t<=2^-3187` и independent reader error `xi_t<=2^-3169`, при `eta_j=0`; это не установление требуемой tolerance для каких-либо реальных readers. Нормализованные source effects и другие observables могут иметь другие нормы; следует использовать фактическое `||O_t||`.

Полный Book covector дополнительно требует реальных heat/clock, old-prefix, price-reading/finite-comparison и `E_tau` оценок с правильной нормировкой на `Gamma_s`, настоящим signed displacement и оплаченной длиной. Их малость не следует из (1)–(7); физический `C` и ОТО остаются открытыми.
