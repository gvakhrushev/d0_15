## 1. Зафиксированная исполняемая компоновка

После настоящего NPS/E0 оставляем весь его prefix. На живых `port,r,t,Spin` выполняем:

1. 36 исходных вызовов обратного эхо B17: `CX(r,t); routed G_t^-1; CX(r,t); routed G_t^-1`.
2. Шесть отдельных канонических рождений `v=(sqrt(p),p)` на новых адресах. Они происходят до подготовки всех шести нулей.
3. Шесть настоящих 17-call routed inverses, всего 102 вызова.
4. Ровно 30 исходных CX для четырёх port round trips, четырёх raw copies и двух validity copies.

Итого **174 новые стадии**, включая все шесть рождений. Последняя операция — настоящий `CX(port,t)`, а не добавленный бесплатный identity tick. Spin восстанавливается исходными маршрутами на всех колонках. Все invalid и inactive записи остаются. Детерминированная шестибитная запись равна `(r,t,r,t,t,r)`.

Это конкретная разрешённая компоновка данной подпрограммы. Она не притворяется полным исполнением H.1: обязательные поздние тесты, компараторы остановленного first-repeat и последующий controller при наличии исполняются отдельно. Нельзя перенести фиксированную длину данной подпрограммы на всю остановленную историю. Ранее исполненные стадии E0 не вычитаются.

Пусть перед добавлением размер полного живого носителя равен `d`, число выполненных стадий prefix — `N_<`, сумма их **предстадийных** размерностей — `D_<`. Пассивный oldRIGHT уже входит в `d`. Тогда

```
N = N_< + 174,
d_final = 64d,
D = D_< + [36 + (1+2+4+8+16+32) + 132*64]d
  = D_< + 8547d.
```

Новые birth details имеют ранги `(1,2,4,8,16,32)d` и возраста `(137,136,135,134,133,132)`. Каждый прежний detail получает ровно 174 дополнительные реальные стадии; поэтому прежняя сумма возрастов увеличивается на `174d`, а новые details добавляют `8373d`. Оба независимых подсчёта дают `8547d`.

После последнего рождения исполнено 132 унитарных вызова, включая последний настоящий gate. Поэтому минимальный возраст **L=132**, независимо от длины и рождения в старом prefix. Если после reader исполняется ещё `s` унитарных стадий без рождений, `L=132+s`, `D=D_<+8547d+64sd`. Позднее рождение меняет эту оценку и должно учитываться заново.

## 2. Именно полный растущий clock

Обозначения G1–G6: `K=⊕H_j`, реальные `F_j`, пассивные включения `B_(j,f)`, birth complements `D_j`, полный `R:H_f→K` и `T=S+RgE_f`. На рождении `F_j` — изометрия с полным новым complement, на унитарном шаге — исходный gate. Следовательно `T*T=TT*=I_K`. Никакой terminal complement не отброшен.

Каноническое завершение для winding determinant необходимо вычислять по **возрастам рождения**, а не просто продолжать ранние gates тождеством на ещё не рождённые биты. Если

```
U_(j,f) = g F_(N-2) ... F_j,
Pi_j = B_(j,f) D_j B_(j,f)*,
W_can = Σ_j U_(j,f) D_j B_(j,f)*,
```

с `D_0=I`, то `W_can` унитарен: его ортогональные input details и реальные forward images образуют полные разложения единицы. Именно для него

```
det(I-zeta T) = det(I-W_can Σ_j zeta^(N-j) Pi_j).
```

Все степени справа начинаются с `L=132`. Поэтому `Tr(T^n)=0` при `1<=n<132`, включая производные по всем разрешённым gate-направлениям при неизменной birth layout. Это утверждение обо всём операторе, а не о среднем на выбранном входе.

Три независимых малых контроля в checker непосредственно строят `T` на неравных пространствах стадий и проверяют обе determinant-формулы. Отдельный отрицательный контроль действительно отвергает наивный padded raw endpoint: он даёт неправильный winding polynomial. Он не является заменой `W_can`, хотя совпадение на исходном born input может сохраняться. Для настоящего большого reader применяется доказанная общая формула и его точный список стадий; огромная полная матрица H.1 не собиралась.

## 3. Весь первоначальный тепловой вклад

Сохраняем исходную сцену с 33 вершинами и 359 рёбрами, обе Hodge-степени, `beta=2p²` и нормировку owner:

```
Z = 2 Tr_(33D) exp(-beta Delta_0(T)) + 359D,
H = log(Z)/beta,
full modes = 425D,   Z >= 359D.
```

По CL7–CL8 при `x=2/55`:

```
|DH[v]| <= A_L ||D W_can[v]||op,
A_L <= (176/359) x^L / [L! (1-x²)(1-x/L)].
```

Для буквальной компоновки выше правая часть при `L=132` равна

```
A_132 <= 4.4736145391782206614948384156650793 * 10^(-415).
```

Checker вычисляет эту верхнюю границу **точной рациональной дробью** и проверяет `0<A_132<10^(-414)` без округления. Десятичное значение — только отображение дроби. Большое число действительных архивных стадий уже делает этот heat coefficient малым; дополнительная clock padding для самой этой оценки не требуется.

Это не безусловная оценка нормированного physical residual: остаются настоящий полный occurrence norm и положительный gain:

```
||DH/Gamma||_(full,*) <= A_132 C_full/Gamma,
||D W_can[v]||op <= C_full ||v||_full.
```

Каждая старая и новая независимая унитарная операция учитывается отдельно. Для gate-max chart с unit lifts достаточно суммы всех реальных occurrences; настоящее geometry/right-lift преобразование оплачивается собственными коэффициентами. При конечном сравнении с одинаковыми layout и length применяется исходное

```
|H_+−H_-|/(2|t|Gamma)
 <= A_132 ||W_can,+−W_can,-||op/(2|t|Gamma).
```

Следовательно не требуется производная дискретного индекса программы. Нельзя объявить абсолютную малость нормированного residual, пока `C_full/Gamma` не ограничено. При необходимости действительные `CX;CX` после последнего рождения дают CL12 с новым `L,D` и всеми их occurrence rows. Ни их work, ни абсолютное `log Z` не вычитаются. Независимые scene, beta, zeta или variable birth rows этой gate-оценкой не покрыты.

## 4. Унитарная запись и измеренный канал — разные операнды

Реальные шесть копий — унитарный retained archive с каноническими рождениями. Операционный PVM на его метках задаёт вероятности fine-результатов; он не удаляет уже сохранённые копии и не превращает исходный полный born cut в payload-only cut. `report_bits` в native grammar — только metadata, не дополнительный measurement primitive.

Если дополнительно выполнен необратимый dephasing/channel или внешний measured controller, его настоящая dilation, retained environment, stages, births и выбранный cut должны быть заданы. Нельзя вставить CP map в доказательство `T*T=I` и сохранить старые `425D`. Checker содержит простую проверку этого различия: dephasing чистого qubit меняет purity, поэтому унитарным шагом на том же носителе не является.

Для полного унитарного архива G9–G10 дают именно исходный feedback

```
C = P0 B_(0,f)* g A_f P0,
det(I-zF) = det_Im(P0)[(1-z)I+z C*C].
```

Он не равен прежнему короткому `f(q)^2` и не обязан равняться dephased payload probability. B18 вычисляет его банковские коэффициенты. В частности, нулевая tail-row одной A8 code/CQ цены не позволяет занулить `DJ`: у полного архивного возврата может сохраняться первая производная по независимому bright-tail углу. Она должна оставаться в общей системе или сниматься доказанным полным optimum/controlled residual.

## 5. Достигнутая граница

Снята конкретная предпосылка: для **буквальной унитарной подпрограммы** новый полный тепловой источник теперь имеет доказанную оценку с настоящими стадиями, рождениями и всеми `425D` модами. Прежний короткий heat не использован. Остались настоящая полная cold/ledger/source композиция, допускаемые будущие reader transports и исходная physical Cost−Info binding. Весь first-repeat controller и весь H.1 не объявлены воспроизведёнными.
