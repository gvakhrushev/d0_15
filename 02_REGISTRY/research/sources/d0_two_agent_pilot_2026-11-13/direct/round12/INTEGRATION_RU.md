# A12 + B25/B26: что уже подставляется в исходный H.1

Фаза: native realization существующего полного источника; не новая физическая модель. Потребитель — исходный fixed ten-sign H.1 и семивызовный компаратор, затем A10 recovery на том же полном tape. Входы — A11 full tensor DAG и periodic binding, B21 fixed-collar chart, B24 frame/boundary transport; исходные физические владельцы и hash закреплены в receipt.

## 1. Конкретная подстановка

1. B25 задаёт вычислимые полные Julia/CAR и внешний SITE targets для всех семи вызовов на одном `A=2049`, `S=256`, raw-u chart. Внутренние CAR/Fourier и их свежие RIGHT отделены от одного внешнего PF SITE. `Y0` и all-zero SAM vertex различаются.
2. Его адресованный source binding — неизменённый A11: каждый выбранный rank-two moment теперь имеет конкретный входной/выходной индекс того банка, к которому применяется. `rho^-1` вводится один раз в A12 top selector.
3. A12 реализует математическое среднее каждого полного source operator через независимые signed involutions. Identity padding и offsets по типам копий дают равенство операторов на коррелированных входах, а не только правильное ожидание на product states. Selected-source Hadamard test пока остаётся целевой логической операцией.
4. Три prefix palettes содержат все целочисленные thresholds. Их ровно фиксированные cap и padded slots позволяют вычислить component READY. Это готовый вход для Boolean compiler, а не оценка ещё не выписанного native processor.

B25 full-column `O_b` и `O_b (G^tensor22)^T` различаются: второй — целевая рамка настоящих RAW births. Только `O_b` фиксирует padding по отдельности. Полный RAW macro может его смешивать. Изоляция unknown oldRIGHT следует из явного identity factor, не из проверки одной численной колонки. Положительный Julia/material slack гарантирует определённость target formulas на всём данном SAM cube; численные target diagnostics сами по себе не доказывают native/C1 compilation.

## 2. READY и retained environment

Для palette-control j целевая prefix isometry имеет вид

```
W: |j> |coin> |0> -> |j> |coin> |label_j(coin), work_j(coin)>.
```

Все исходные coin strings, suffix, work и failure flags остаются. Из общего τ и ортогональности сохранённых j следует `W^* Pi_READY W=tau I` на входном control. При последующем выборе `V_label` с тем же control получается нужный block-diagonal source observable. Это не означает факторизацию выходного окружения как одного вектора, общего для всех j.

Точный hostile пример B26: `|0> -> |0>|0>`, `|1> -> |1>|1>` имеет READY effect I, но разные retained states. После трассирования окружения теряется межконтрольная когерентность. В A12 окружение не трассируется и не заменяется новой энтропийной ценой. Чтобы связать actual H.1 `A_b,t`, `O_t`, reverse, clock и seal, потребуется полный gate-level transport этого окружения. Нельзя вывести его из одной scalar α или вероятности report.

## 3. Независимая проверка и точный предел вывода

B26 (`a5bd92bfa3f55d7433225ea7e017ef748b67a6dd`) независимо пересчитал 20 402 node masses/degrees, все 3618 reachable add nodes, 25/512/2048 partitions и 54 report coefficients; compiler/verifier дали пять побайтно совпавших outputs. Root проверил неизменность всех входов/выходов receipt B26 и содержание доказательства; checker B26 повторно не запускался без изменения входа.

B25 (`38f7ee2c49ee9bba96a024259caf181b55cf7f29`) проверен root в изолированной копии. `review_b25.py` воспроизводит `check_targets`, `check_raw_frame`, `certify_reference_slack`, `build_mark_catalogue`, `check_bound_leaves`; девять outputs совпадают побайтно. Сопоставление B25 bindings с A11 проверено на двух настоящих параметрических входах, всего 1 010 688 моментов. Это целевые матрицы и численные диагностики; source-scale и fixed boundary assumptions не менялись.

Следующие обязательства имеют конкретные входы: reversible prefix/rank/threshold/first-success compiler; controlled signed-pair swaps и фазовые операции; полный admitted native schedule со всеми ресурсами и fail branches; его full READY, marked maps, reader, births/cost/clock; физическая связь исходного Cost−Info с полной историей и source. Ни одно из последних требований не закрывается текущим component bound.

Физическое `C` из §7fu по-прежнему не доказано. Новая Info, подобранный коэффициент или самостоятельный закон выбора не вводились. `GR_closed=false`.
