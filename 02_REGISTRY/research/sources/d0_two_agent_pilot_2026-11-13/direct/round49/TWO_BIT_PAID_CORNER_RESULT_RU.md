# A49: фактический corner, фиксированный post и оплаченная четырёхслотовая семья

Закрыта следующая математическая предпосылка A48: для его конкретного
двухбитного источника построен конечный рецепт фиксированного post и одной
семьи с четырьмя независимыми control slots, реально исполняемым дополнением
до равных длин и общей формулой часов. На объявленной canonical RAW fibre
закон A27 даёт `||Mhat−Mideal||<2^-3421` и `Mhat_b>2/3`. Тем самым выполнен
corner-порог A47 `<2^-3298` для **выбранной typed extension**.

Полный production word и его колоссальная сумма путей не вычислялись.
Это конечный конструктивный рецепт с доказанными оценками, проверенный
на малых исполняемых примерах; практическая исполнимость не заявляется.
Исходные физические Dν/marks, эквивалентность первоначальному vacuum
descriptor, все независимые источники полной цены и Cost−Info selection
остаются открыты. `physical_C_closed=false`, `GR_closed=false`.

## 1. Потреблённый результат и область

Вход — A48 (`a01426087370e45bbb840052bb8b62899bf7bb57`): 5376 CODE bits,
11893774624 ранних RAW births, полная SOURCE-DATA prefix error `<2^-3423`
и canonical compressed core error `<2^-3421`. Используются прежние A47
контроли, A27 product-moment law, A46 восьмой независимый bank, A41/B80
универсальный post и исходный Book reader. Новый action, коэффициент Info,
source selector или геометрический root не вводились.

Два разных утверждения не смешиваются: prefix error относится к полной
SOURCE-DATA fibre до REPORT, а corner error — к canonical compression
всего comparator. Независимые insertion rows не следуют только из corner.

## 2. Реальное дополнение до длины

`paid_padding.py` за один проход считает фактически порождённые G/CX с
учётом повторений. После source stream он исполняет требуемое число
реальных CX из identity-слов длины 2 и 5. Для гарантированного представления
резерва оставлены четыре вызова. Метки сохраняются на фактических native
layers. Верхняя оценка старого слова не объявляется его точным числом
вызовов: exact длина принадлежит **новому дополненному слову**, при
завершении конечного stream и выполнении доказанной верхней оценки.

Каждый из четырёх A47 controls уже имеет свою точную длину; дополнительно
оплачены четыре CX в каждом слоте. Дополнительные 16 calls входят в общий
`L_base`. Core, fixed post и отдельный post-probe также имеют собственные
реальные дополнения. Поэтому все варианты используют один carrier и
одинаковые длины, включая неактивные слоты.

## 3. Target из фактического G/CX core

`finite_actual_target.py` вычисляет scalar `Mhat_b` суммированием настоящих
G/CX paths и RAW amplitudes WORK. Здесь нет готовой таблицы идеальных
targets или необработанного production-запроса. CODE может иметь
несмежные и несортированные физические адреса. Каждый G/CX target обязан
быть WORK. Адаптивная интервальная арифметика даёт наружные границы.

Отсутствие вектора из `2^n` компонент не делает метод практически быстрым:
число путей огромно, и один WORK-index тоже требует растущей памяти.
Production scalar entries, полный post и полный native tariff не
вычислялись. Терминирующий математический рецепт не доказывает оплату
классического вычисления компилятора исходной физической ценой.

Положительность Mhat позволяет задать

    r = ||Mhat χ||,
    h_b ∝ χ_b (1 + Mhat_b/r),
    U = R_χ R_h,
    U Mhat χ = r χ.

Нормировка h сокращается в Givens ratios. Четыре списка A41 stars
компилируются настоящим B80 интервальным выбором степеней. U заморожен
в центре и один для всех сравниваемых историй. Ошибка на всём CODE:
`e_U<2^-9247`. Это full-operator bound, а не только точность одной колонки.

## 4. Четыре независимых места вставки

Хронология семьи:

    P_f ; B ; Q_f† ; middle ; Q_b ; return ; P_b† ; fixed U ; post-probe.

В matched варианте физические знаки четырёх controls: `(+,-,+,-)`.
Самостоятельные P_f, Q_f, Q_b, P_b arms сохраняются отдельно. Последний
P_b расположен **до** fixed U. Отдельный probe после U — другая basis;
его stationarity не подменяет строку P_b без доказанного транспорта.

На 13 малых фактических histories проверены centre, ±matched, восемь
независимых control arms и два post-probe arms. Проверены обе source marks,
равные lengths, все RAW births, сохранение заключительного G и clocks.
B95 exact counterexample показывает, что `[Q,S]=0` само по себе не
обнуляет две Q-строки: они могут быть ненулевыми и противоположными.

## 5. Corner и нормировка исходного reader

Все новые точки `2^-80(d−3p²)`, d=0,1,2,3, лежат в прежнем B21
asymmetric cube, поскольку `3·2^-80<2^-30`. A27 leaf identities
сформулированы для всех labels с определёнными source targets, а не
только для двух старых имён. Сохранены copy offsets, общий SITE,
исходные семь REPORT и SC6 polynomial.

Восьмой fresh REPORT сокращается в **идеальном** замкнутом comparator,
поскольку он коммутирует с SC6 и его Z. Коммутативность со всей RAW frame
не требуется и не предполагается. Actual REPORT использует общий helper;
его native error остаётся в A48 bound и не удаляется этим сокращением.

B96 проверил CODE-control-only grammar всей конструкции: все 1568 source
bindings, 4214 coframe family/width classes, material rotations, proper
mode pairs, SITE/REPORT/SC6/resources и A29 lowering. Это compositional
proof, без развёртывания всех масок и гигантского слова. Поэтому actual
canonical compression действительно диагональна на CODE. Получаем

    Mideal_b = 1 − 2 κ9 p^7 (4 + Σ_x w_x Ξ_bx)
             = c_ref − 2 g Iτ(Y_b),
    ||Mhat − Mideal|| < 2^-3421 < 2^-3298,
    Mideal_b > 67/100,       2/3 < Mhat_b ≤ 1.

Из `p^7=13p−8`, κ9≤1 и рациональной верхней границы p следует
`c_ref=1−8κ9 p^7>2/3`. После fixed actual post `c0hat>2/3`. С прежним
`g>2^-3128`, σ=2^-80, z=2^-20 исходный Book reader имеет нормировку

    Γ = 4 z p^K c_ref gσ / (1 − z + z p^K c0hat²)
      > (8/3) z 2^-3208 p^K.

Это нормировка данной candidate family, не новое определение g и не
доказательство, что эта семья выбрана физическим Cost−Info.

## 6. Общие clocks и проверенные остатки

Пусть L_base — сумма новых exact padded body lengths, n — все ранние
births, K — поздние retention пары. При пустой начальной истории:

    N_base = n + L_base,       N_base.bit_length = 30833,
    K = 175604,
    N = N_base + 2K,
    D = 2^n (L_base − 2 + 3·2^K) − 1,
    native calls = L_base + K.

Полные целые значения записаны шестнадцатерично в
`TWO_BIT_PAID_FAMILY_PLAN.json`. Размерностный перевод для m=5376
использует долг m+ceil(m/2)=8064, без замены огромной basis одним axis.
При указанном gain и прежнем reader получены:

| Остаток | Проверенная верхняя оценка |
|---|---:|
| Fixed post operator | `2^-9247` |
| Independent post skew dual finite feedback | `2^-661` |
| Heat full skew dual | `2^-75` |
| Shared SOURCE/control local interface, после деления на исходный g | `2^-189` |

Последняя оценка использует один и тот же E=Bhat−Bideal в двух arms:
сокращение даёт `2 e_SOURCE/(gσ)+2 ε_P/(t gσ)`. Actual P− не считается
точным inverse P+. Полный vector-jet bound `2^-44` не делится на g.
Ни одна строка этой таблицы сама по себе не оценивает весь physical source.

## 7. Воспроизведение и следующий потребитель

Собственный проверяющий расчёт прошёл: exact малые Q4 kernels, интервальные
post ratios, настоящая B80 power, star grammar, оплаченные histories и
production integer bounds. B95 дал независимые slot/price identities,
контрпример автоматическому Q-zero и exact quadratic scalar cancellation
на исходном product. B96 независимо проверил schedule, target, footprint,
corner и gain. Root повторил все три B95 и все семь B96 checks с
побайтным совпадением JSON; записи в чужую рабочую копию были запрещены.
Все source hashes и B96 Git blobs проверены. Это не Lean-формализация.

Следующий точный parent step — четыре независимые price rows этой же
истории с переносом **всех** insertion errors. Для scalar lift необходимо
потребить B95 quadratic cancellation, получить third-derivative remainder
исходного Iτ и отдельно учесть коррелированный вес fixed post. Product
lemma не переносится на него автоматически. Затем остаются original Dν
и vacuum descriptor, WORK/scene/record/Info/preparation variations, полная
Cost−Info binding и физическое refinement. Нулевой matched отклик не
означает нулевые независимые строки или вывод ОТО.
