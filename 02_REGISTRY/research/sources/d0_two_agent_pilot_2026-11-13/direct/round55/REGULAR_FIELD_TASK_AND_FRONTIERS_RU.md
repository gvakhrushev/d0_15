# A55. Одна задача со свободным полем и действительными retained prefixes

## Подстановка в родительское утверждение

A54/B105 уже дают native SOURCE и полную оплачиваемую семью для каждого
рационального имени поля. A55 превращает их в конкретный запрос
`(field, label)` при **одном фиксированном constructor c** и связывает
его со словом, births, post, clock и тринадцатью объявленными marks.
Свободное поле не замораживается в старом A49 centre. На двенадцати
завершённых post-Qf frontiers перенесена исходная full-vector/effect
оценка A47/A51 с новым uniform SOURCE error.

[Конструктор](regular_comparison_task.py),
[пакет](REGULAR_COMPARISON_TASK.json),
[проверка](check_regular_comparison_task.py),
[receipt](REGULAR_COMPARISON_TASK_CHECK.json).
К нему применяется отдельный B107 off-shell price-source recovery.
`physical_C_closed=false`, `GR_closed=false`.

## 1. Конечные запросы при одном c

`Request` содержит A53 `FieldCentre` (2688 независимых рациональных
смещений, `|y_j|<2^-32`) и исходный строго проверяемый A52 `Label`.
Каноническое JSON кодирование сохраняет точные числители/знаменатели и
label; обратный разбор требует полного round trip. Скрытый program/reader,
неизвестный field и лишние ключи не принимаются. Неканонические fractions,
bool вместо integer, выход на границу chart и неверные slots отвергаются.

При каждом фиксированном поле остаются 26881 обычный label: centre,
matched и четыре независимых arm по 2688 axes и двум знакам. Отдельный
конечный каталог post-probe состоит из всех пар CODE basis labels и знаков.
**Объединение всех рациональных полей не является одним конечным
каталогом.** Каждый конкретный запрос читает конечное имя и конечный
label. Это локальная finite-input форма task datum `(c,d)` EOQ10;
действительная section в raw verification space всё ещё требует своих
operator/response/projection свидетелей.

В c фиксированы выбранная A23 полная vacuum extension, A54/B105 алгоритмы,
точности, область, полный reader, исходные p/z/beta, clock profile и
правило выбора actual post. В d меняются y и label. Никакой Einstein
predicate не участвует в допуске. Сгенерированные words, cuts и lengths
не выдаются за дополнительные независимо настраиваемые параметры.
Как разрешает EOQ10, это task data, без утверждения о бесплатной загрузке
физического program register. Фактически исполняемые parser/compiler/
calculator должны сохранять собственные оплаченные стадии.

`FieldTask(y)` имеет собственный B105 instance. Его `ActualDiagonal`
ссылается непосредственно на **его** A54 `source.core_blocks`; post
вычисляется из actual M(y), а не из M(0). Два знака, axis и все slots при
этом y используют тот же post. Запрос другого поля отвергается этим
instance; другой instance имеет собственный post cache. Одинаковые
канонические значения y после decode допустимы, даже если это другой
Python объект. Guard B105 проверяет привязку самого источника и вложенных
компонентов перед потреблением.

У каждого запроса новый B105 common `Lbase/Nbase`, `K=175604`,
`N=Nbase+2K`, `D=2^n(Lbase−2+3·2^K)−1`, `n=11893774624`.
Они относятся к действительно дополненному identity слову. Вычисление
полного giant word или path-sum не заявляется. `H0=C` и rank-one input
остаются прежними; широкий SOURCE-fibre theorem их не расширяет.

## 2. Ровно те же prefixes внутри нового слова

Для label a исходные знаки slots определяют полную последовательность

    Pf ; B(y) ; Qf† ; middle ; Qb ; return ; Pb† ; U_post(y) ; probe.

A55 prefix на completed mark ν имеет буквальный вид

    Pad(Pf) ; actual SOURCE_prefix(y) ; Pad(Qf†) ; actual D_ν.

Для `SOURCE_before_Qf` последние два участка отсутствуют. Qb/Pb/post и
retention не переносятся назад. Дополнение core до общей длины находится
после полного возврата, поэтому на ранний SOURCE mark оно не добавляется.
Копии такого prefix для independent Qb/Pb/post-probe имеют свои правильные
нулевые ранние controls; их поздние изменения остаются в общем слове.

Двенадцать completed marks: `SOURCE_after_Qf`, `RAW_frame_return`,
восемь `REPORT_j_complete`, `PORT_ZERO`, `SC6`. Это те же реальные A17
report/READY выходы и inherited B58/A51/B100 закрытые границы transducer.
Действительный D_ν не меняется с y: A54 меняет только SOURCE stages, а
processor stage list не содержит SOURCE/SITE/SIGMA. Новая обвязка вызывает
непосредственно stage provider данного A54 instance, затем тот же compiler
и physical map. CODE-disjoint support и все private/failure/remainder
остаются у D_ν; matched identity не переносится на произвольный early cut.

На двух независимых конечных noncommuting source fixtures исполнены
598 полных сравнений буквальных prefixes с prefix всего padded слова:
23 вида labels × 13 marks × 2 поля. Дополнительно проверены field-bound
actual target factory, совпадение нового common clock, неизменённый
processor provider и первые реальные birth stages. Эти проверки не
выдаются за исполнение production SOURCE.

## 3. Uniform full-vector и effect first jet

На всей новой коробке, вместе со всеми CODE points, A53 сохраняет старые
B21 slacks. Поэтому B91/A47 дают те же **operator** bounds полного
идеального SOURCE: `M1=1748`, `M2=3233036`, `R_v<104`.
Для каждого y сравниваются actual independently compiled controls с
`σ=2^-80`, `t=2^-1700`; слово SOURCE при этих двух signs фиксировано.
Дифференцирования discontinuous grid selector по y здесь нет.

Пусть eB — новый A54 all-DATA SOURCE prefix error, eP — исходная A47
operator error controls. Потребление исходной MG2/MG3 identity даёт

    e_extra = (eB+2eP)/(σt)+(4/3)·104·M1·t² <2^-1642,
    e_jet,B = σ·104²·M2+e_extra <2^-44.

Для retained processor берём все восемь REPORT, даже на более раннем
mark, и новый full replacement bound. Получается `eD<2^-4058`. Actual D_ν
одинаков в обоих arms и точно CODE-disjoint, так что его вклад равен
`eD·M1`, а не `eD/(σt)`:

    e_jet,ν = e_jet,B + eD M1 <2^-44,
    e_mid,ν = σ·104·M1 + eB + eD + 2eP + 2t² <2^-62.

Область — все выбранные SOURCE DATA/SITE columns с canonical
source-private/factory RAW inputs и произвольной внешней запутанностью.
Произвольные dirty private не добавляются. Для любого фиксированного
joint effect O с `||O||≤1` и сохранённым полным output формула

    (F+* O F+ − F−* O F−)/(2σt)
      = Fbar* O J + J* O Fbar

даёт error `<2 e_jet,ν+2M1 e_mid,ν <2^-43`.
Это неусловный effect; success-conditioned статистика имела бы собственный
denominator. Для approximate real field name нужно отдельно добавить
ошибку имени из A53/B91; ни все вещественные поля, ни произвольная
physical V_h norm не заменяются рациональным packet автоматически.

## 4. Связь с off-shell ценой и оставшиеся границы

B107 потребляет это же A54/B105 семейство и получает для fixed-y control
covector исходного H+J и actual Γ(y) target

    (DIτ(Y), −DIτ(Y)/2, DIτ(Y)/2, 0),  Y=Y0+y,

с координатной ошибкой Pf/Qf/Qb `<2^-108`, Pb `<2^-189`, общей Euclidean
ошибкой `<2^-102`. Вне центра DIτ(Y) не объявляется малым. Эти величины
относятся к четырём независимым MG2-control comparisons при данном y,
а не к полной derivative задачи, в которой меняется также U_post(y).
После stationary reduction moving-source term сохраняется; одного этого
результата недостаточно для всех логических/внутренних equations.

При faithful реализации запрос относится к полной операции
`E(word)=E(actual_reference(c,Y,label))` с теми же birth boundaries,
retained complements, marks, input, cut и closing gate. Owned FN/RAW
переносят цену при доказанном равенстве этого tuple. Разные Y и разные
labels не считаются одной вертикальной fibre лишь из-за общего c.

Четырёхисходные математические тесты исходных REPORT/READY остаются
доступными по A52, но измерение на intermediate mark здесь не вставлено.
Не заявлены actual registration/fine instrument или бесплатный decoder
после suffix. A23/B25 остаётся **выбранным** полным продолжением: совпадение
с иным первоначальным descriptor либо допустимый marked transport нужно
доказать. Никакие исходные D_ν не подменяются только похожими outputs.

Открыты actual Book01 response/projection witnesses, физическая V_h/right
lift и полнота допустимых source directions, independent input/WORK/scene/
record/Info equations, same-execution Cost−Info и refinement к ОТО.
Фиксированный c с меняющимся полем делает следующий перенос конкретным;
сам по себе он не выбирает физический закон и не завершает вывод ОТО.
