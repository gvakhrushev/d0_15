# Исторический v3 поиск на cbe7: компактное свидетельство

На закреплённом снимке `cbe7de75dbc92273db10dfaabf7e3d31fdf9f204`
сохранены исходный полный producer JSON, полная проверенная сводка, оба журнала прогресса и их хеши.
Это историческая проверка поиска, не повтор на текущей ветке и не научная
приёмка найденных утверждений. `GR_closed=false`.

В исходном producer-результате обнаружение оставалось `unattested`. Затем
сводка компактора, использовавшего `--verify-discovery`, фиксирует повторный
пакетный поиск **той же реализацией**, перепроверку доступных страниц и
`50/50` сценариев: 414 запросов, 415 строк требований со статусом
`found_direct_content`; отдельный тест влияния изменений имеет статус `pass`.
Всего `benchmark_cases_total=51`: последний элемент — тест влияния, а не
ещё один поисковый сценарий. Размер окна и число страниц ранжирования —
18 и 2; источники корпуса (4 396 файлов) сверялись на конечных точках.
Это не независимая реализация поиска, не непрерывная аттестация среды и не
семантическая проверка каждого текста; смысловой review остаётся ручным.

Из 415 строк у 112 присутствуют одновременно явные поля commit и blob;
они дают 107 уникальных пар commit/path/blob, которые дополнительно сверены
с локальными Git-объектами. Три строки с `source_origin=pinned_snapshot`
не содержат обоих явных полей commit/blob на уровне строки. Прочие
300 строк имеют `source_origin=workspace`. Наличие прямого содержательного
совпадения нельзя подменять утверждением о 415 отдельных Git-pins.

[manifest.json](manifest.json) фиксирует хеши данных до и после сжатия.
`summary.json.gz` содержит все случаи, найденные строки и ограниченные
текстовые evidence-сниппеты; `producer_progress.jsonl.gz` и
`compactor_progress.jsonl.gz` — исходные потоки прогресса. В журналах нет
отдельно записанных кодов завершения процессов; это не доказательство их
кодов. Сама сохранённая сводка содержит полностью сформированный результат
проверки и хеш полного входа.

## Полный потоковый архив и восстановление

Полный исходный producer JSON размером 752 668 795 байт имеет SHA-256
`6e765423fd16c960576d60590ad9b7c9de461226b9560c6d86c23481135fda9c`.
Он сохранён в трёх последовательных частях одного gzip-потока в `parts/`
(102 743 098 байт суммарно); `archive.json` фиксирует хеш каждой части,
общего gzip и восстановленного JSON. Потоковая проверка сравнила все
восстановленные байты с `/tmp/d0_v3_full_cbe7.json` без создания второй
полной копии; исходный файл не удалён. Архив `b308` относится к другому
снимку и не подменяет этот результат.

Проверить полный архив без записи восстановленного файла:

```sh
python3 02_REGISTRY/research/sources/d0_proof_architecture_formalization_2026-10-24/reports/cold_start_v3_cbe7_compact_2026-11-06/verify_archive.py
```

Чтобы восстановить файл, добавить `--extract /tmp/new-cbe7-v3.json`;
назначение должно отсутствовать. При ошибке потокового восстановления
частичный новый файл может остаться и не должен считаться проверенным.
Для потокового сравнения с доступным исходником предусмотрен `--stdout`.
Архиватор не выполняет поиск и не подтверждает семантику.

Проверить сводку, журналы, счётчики и явно закреплённые Git-pins:

```sh
python3 02_REGISTRY/research/sources/d0_proof_architecture_formalization_2026-10-24/reports/cold_start_v3_cbe7_compact_2026-11-06/verify_receipt.py --verify-git-pins
```

Если исходный raw-файл сохранён отдельно, добавить
`--check-raw /path/to/full-cbe7.json`: проверяется размер и SHA-256.
Проверка Git-pins требует наличия соответствующих Git-объектов.

Для нового полного выполнения использовать **чистую рабочую копию именно
cbe7** с исходными Git-объектами и окружением; не заменять исходные версии
скриптов версиями текущего HEAD:

```sh
python3 tools/proof_architecture_cold_start_v3.py > /tmp/cbe7-v3-replay.json 2> /tmp/cbe7-v3-producer.log
python3 tools/compact_proof_architecture_cold_start_v3.py --input /tmp/cbe7-v3-replay.json --output /tmp/cbe7-v3-summary.json --verify-discovery 2> /tmp/cbe7-v3-compactor.log
```

Это заново исполняет оба этапа и может быть ресурсоёмким; совпадение хеша
нового raw зависит от совпадения фактических входов и условий выполнения.
Код не аттестует незафиксированные библиотеки, Git-объекты или среду между
двумя проверками. Копирование старой сводки или статус Lean/CI не являются
новым выполнением поиска.
