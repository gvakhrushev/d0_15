## Новый запуск

Нужен Python3 с SymPy1.14 и mpmath1.3; NumPy, Lean, сеть и новые установки для этих проверок не нужны. Из корня репозитория:

```bash
python3 02_REGISTRY/research/sources/d0_three_text_reconstruction_2026-10-21/replay.py
```

Проверка только сохранности артефактов и исходных Git-объектов:

```bash
python3 02_REGISTRY/research/sources/d0_three_text_reconstruction_2026-10-21/replay.py --integrity-only
```

`--output /absolute/path/new-result.json` сохраняет результат нового запуска. Сохранённый интеграторский [REPLAY_RESULT.json](REPLAY_RESULT.json) относится к текущей реконструкции. Ранние новые worker/independent receipts сохранены отдельно с собственной датой/средой; старые counts из пользовательского текста не присваиваются новым проверкам. Проверки используют явные исключения, не отключаемые ключом `-O`.

Целевые проверки: исходные матрицы и positive effects; полные first jets неуспешных ветвей; точные flag moments, score normalization и ковариация; нелинейный odd defect и clock term; finite-bank complete price и fresh-bit control; coupled auxiliary inverse/Schur, полный null source, конечная lambda и аналитическая all-cap bound; независимый 85-digit section diagnostic. Конечные контрольные разбиения и cap не заменяют приведённые общие аналитические доказательства.

В oriented finite-tree fixture семнадцать исходных категорий взяты как атомы свежего query law. Сохраняются весь новый raw Golden bank, оба query, stop/unresolved и fresh continuation. Этот расчёт проверяет полную классическую модель указанного интерфейса; он не доказывает, что все внутренние quantum/fine records исходного физического query уже совпали с семнадцатью категориями. В общем доказательстве такие записи входят в полный `P_P` и его цену, а не выбрасываются.
